# 小米遥控器麦克风键分流实验

状态为草稿。目标设备是 MiTV-MFTR0，目标遥控器为 USB 厂商/产品标识 2717:32b8 的蓝牙设备。按键使用已有电视阵列通话入口，再按展开原通话。电视本体的“小爱同学”继续由小米处理。

原厂同时分发 Android 键事件（keyCode 0，scanCode 63）和蓝牙 ATVV 控制消息。短按会由 com.mi.bluetooth 显式调用小爱的 VoiceControlService，长按及抬起使用另外两个 action。此前仅消费 Android 键事件的版本已被实体测试否决。现有小爱近场 Morpheus 接口还要求签名白名单和前台包名，当前 V 签名未列入。

## 集成条件

此目录的 XML 是 Android 系统 Intent Firewall 的集成资源。系统集成方需要把它作为独立文件放入系统管理的 IFW 规则目录，验证短按、按下、抬起三个 service intent 均被拦截，再启用并绑定默认禁用的 RemoteVoiceKeyService。保留设备现有无障碍服务。规则限定目标组件、动作和发送方应用 UID。小米蓝牙包使用共享系统 UID，因此同 UID 发往同组件的同名动作也会命中。远场唤醒有自己的动作和链路。

MiTV-MFTR0 的原厂 user 构建上，已有认证 ADB 为 shell，SELinux Enforcing，系统规则目录不可写。安装常规 APK 无法完成系统规则集成。本次未在这台电视启用候选。固件更新和回滚必须把规则与组件作为一组维护，回滚时取消实验绑定并恢复组件默认状态，移除本实验的独立规则文件。应复核实体按键、小爱声唤醒及原遥控导航。

## 本地验证

在命名模拟器 FamilyTV_UI 上验证两个独立路径。

- 通过 uinput 注册匹配型号的虚拟蓝牙键盘，发送 Linux scanCode 63。系统绑定的无障碍服务收到 keyCode 0 后启动 V，本地通话 fixture 接通。Home 收起后再次按键，恢复相同 WebView 和通话代次。
- 两个临时测试包模拟蓝牙显式发起服务和小爱接收服务。在原始状态下，目标收到三种按键动作和一个唤醒对照动作。启用 XML 后只收到唤醒对照动作。移除 XML 后四种动作均恢复。测试结束撤销了模拟器规则和绑定。

模拟动作只验证 Android 的分流结果。原厂实体键激活 V、声学唤醒小爱仍待联合验收。
