# Voice direct Makaron CLI repair Candidate

The first Candidate exposed `exec` but Gateway rejected it because no admitted
Agent run owned the secret egress context. The model then delegated the user's
image request. A successful standalone CLI authentication check did not validate
that tool path; the default CLI login was also not the requested personal main
account.

The repair adds a Voice-owned, bounded Makaron CLI adapter behind the existing
`exec` tool. It is opt-in with `VOICE_MEDIA_CLI=1` and an explicitly provisioned
`MAKARON_API_KEY` from the authorized personal account. It never loads the default
CLI account or Gateway secret store. Only the server's fixed personal entry may
use it, with both exec/process present in the live tool catalog. Actor-scoped,
group, anonymous and speaker-routed calls cannot inherit that credential.

Commands are parsed to argv and spawned without a shell. Allowed operations are
image generation/editing with gpt-image-2.5-flare, saving images generated in this
call, fal-h3-max video creation and queries for this call's original task IDs.
Files, environment, models and command options are bounded. Submissions are
serialized and exact repeats reuse their original result, including unknown or
failed outcomes. Cancellation waits for process close; provider cancellation or
refund is never inferred. The model still selects the command and submits the
real result through show_content; no extra media or backend tool is registered.

Gateway admission and production configuration remain unchanged. The former
Gateway admission patch was withdrawn in platform commit 8d5c81c9; this repair
does not revive it. Rollback is disabling the Candidate flag or restoring the
previous isolated Candidate service/artifact.

Validation before live acceptance:
- Full suite: 1,105 passed; focused suite after final changes: 164 passed.
- Actual child-process tests: argv isolation, per-call file/task ownership,
  duplicate/unknown outcome reuse, secret filtering, cancellation and timeout.
- Grok and SeedDuplex protocol tests: local execution to presentation receipt,
  no Gateway exec or backend Agent; identity and live-catalog revocation checks.
- These automated results are not evidence of real model selection, generated
  media, browser playback, physical-device audio or 10–20 second latency.

Live Candidate receipt will record exact source and actual result separately.
