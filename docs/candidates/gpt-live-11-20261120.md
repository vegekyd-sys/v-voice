# GPT Live 1.1 Candidate

Status: Candidate only. Nothing here is released; production Voice and the
Gateway are unchanged and were not restarted.

## What is in it

`gpt-live-11` is a relay model beside Doubao and Grok. The Voice service is
the WebRTC peer to GPT Live (`gpt-live-peer.mjs`, werift + Opus) and the
phone, app and page keep the existing relay socket and screen events. The
model name on the wire is `gpt-live-1.1-codex`, the default voice `sol`.

GPT Live has no function tools: it delegates, and the application works out
from the conversation what is wanted. `gpt-live-router.mjs` turns a delegation
into one call of a tool this call was given:

- one fast function-calling request (the board's model, or the one named in
  `VOICE_GPT_LIVE_ROUTER_*`, 3.5 s timeout) that is given the last turns and
  whether a task is running, so "再看一下" keeps its subject and task controls
  are offered only while a task runs;
- when that gives nothing usable: `delegate_to_v`, so the agent decides. Nothing
  is chosen by a word in the sentence (see "No fixed patterns" below).

The choice starts when the caller stops speaking and is used by the delegation
that follows; nothing runs before the model delegates. The session's own code
validates and authorizes the tool call; the router can never pick a tool the
caller was not given. Results go back as plain facts: search and memory results
without external-content wrappers or links.

## Instructions on the ChatGPT login

The ChatGPT (Codex) login ignores `session.instructions`. A session created
with nothing but "you are a cat, end every sentence with 喵" introduced itself
as ChatGPT, on `gpt-live-1.1-codex` and on `gpt-live-1-codex` alike
(2026-11-20). The first build of this Candidate therefore ran on OpenAI's own
prompt: it called itself ChatGPT, explained things itself instead of asking
for a lesson, and sounded like a generic assistant.

What the model does follow is the conversation it is started with. The
instructions now travel as developer messages in `initial_items`
(`gptLiveInitialItems`), in the structure OpenAI documents for gpt-live-1.1:
name and tone first, then `Backchannel policy`, `Interruption policy`,
`Delegation policy` with `Backend tools` / `Delegate to the backend when` /
`Do not delegate when`. Context appended later (`session.context.append`) is
followed too; `session.update` is refused ("Instructions cannot be updated
after initialization").

## Greeting, explain mode, hang-up

- Greeting: asked for when the call is ready (`session.context.append`,
  speakable) and again every 1.9 s, at most three times, until V speaks. It is
  withdrawn when the caller speaks first, so it is never said in place of an
  answer.
- Explain mode: "讲解 / 解释 / 讲讲 / 科普", a story, or a request for pictures
  becomes `explain_on_board`; the script comes back with the wording OpenAI
  documents for text to be read as written. Its caption is the script itself,
  as far as the voice has got, and the board follows that.
- In two of eight explanation calls the model said "好,我讲讲" and never
  delegated. When the caller's own words ask for an explanation and no
  delegation has come 2.5 s after them, the service prepares the lesson itself
  and gives the script to the session. No other tool is started without the
  model.
- A delegation can arrive before the caller's words are final. The tool call
  waits for them: the session ties a tool call to the caller's last finished
  turn and takes a later one for a change of mind (a hang-up was being
  cancelled by the caller's own goodbye).
- A reply is reported finished after its audio tail. Reported earlier, the
  tail looked like a reply that never ends and everything that waits for V to
  stop speaking waited with it (a lesson script: about 8 s).

## After the first real call on a phone (2026-11-20)

What the call showed, and what was changed for it:

- The caller's words in V's bubble, and on the board. GPT Live reports the caller's speech as it
  is spoken; the service passed those pieces on, and both the page and the board take every
  unfinished transcript for V speaking. The caller's words are now passed on once, whole, as
  the other models do.
- The board did not follow a lesson. With Doubao the script is spoken by its own text-to-speech
  and captioned as written; the board finds the script's words in the caption. Here the caption
  was the model's own text (half-width punctuation, split in two by an interruption), the board
  took it for a new reply and drew a second page from the speech, without the lesson's pictures.
  The caption of a script being read is now the script as written, advanced as far as the model's
  own text has got, and marked as a script (`V-backend-summary`). The board takes any part of the
  script being read for the same page, also when a reading that was interrupted picks up again.
  The model's text runs at most about two seconds ahead of its voice (measured on the long
  replies of that call), which is how far ahead of the voice a drawing can appear.
  On the page, a caption that grows as the script is read does not yet contain the cues further
  on, and a piece whose cue is not in the caption counted as tied to nothing and was shown at
  once; while such a caption is unfinished the page now keeps those pieces waiting
  (`withCuesToCome`). A reading whose opening the model puts differently (a sentence skipped,
  a phrase changed: seen once in the re-test) is found inside what was said and followed from
  there.
- "配上图" answered by a lesson was taken for an unkept promise to create an image: the check
  that repairs such promises sent the model a nudge to start a creation, and cleared the phone's
  audio, as the script began. A lesson with pictures now counts as the promise kept (this path
  is shared with the other models).
- A finished task was not told as a lesson. The session writes a script from the result; this
  model was given it with "tell the user this" and paraphrased it, so nothing was drawn. It is
  now given as a script to read. While the script is written (three to four seconds) the model is
  told the result is in: in the call it answered "nothing new yet" three seconds after the task
  had finished.
- Results waited for the caller to stop speaking (twenty seconds for one task, sixty-five for
  another, while people in the room talked). A result given while the caller speaks is held by the model
  itself until the caller's turn ends (measured: it began speaking at the end of the turn), so
  the service no longer holds it back.
- Memory answers. Each record was cut to 520 characters before the model saw it (Doubao receives
  the records whole): six records of about 3,000 bytes each became 2,400 characters in all.
  Records are now given at the length the search returned them (up to 1,200 characters each),
  with where each comes from and a note that a record describes the time it was written.
- A request for a story with pictures went to the agent and came back as a generated image
  after ninety seconds. Stories and requests for pictures now go to the lesson tool (a script and real
  pictures in a few seconds); a nickname transcribed as a number is kept as spoken.
- Character and voice. V on this model is written as sunny, sweet and gentle, first in the
  instructions. The timbre is the other half and cannot be judged from here: the page offers the
  model's voices (nine work on the ChatGPT login; `marin` is refused), and remembers the choice.

## After the second real call (2026-11-20, late evening)

- "She said she was looking, and nothing happened." A memory lookup had come back; the model
  answered it with "let me think how to put this" and stopped, and to "are you on it?" it said

  turns: whatever it does not say or delegate now does not happen. Three changes: a long result
  arrives in pieces of which only the last asks to be spoken about, and ends with "that is all
  of it, nothing else is running, answer what was asked now"; the instructions say plainly that
  it cannot think or look things up in the background; and a short reply that promises to

- A cough was transcribed as a marker and taken for a turn of the caller's; the board cleared

- Character: sweeter, in the soft manner of speech the caller asked for during the call, at a

- Seen and not changed here: from about 22:30 CST every `tools.invoke` for a memory lookup took
  about 5.0 s longer than earlier the same evening (6.1 s against 1.1 s; the search itself

## "It sounds like reading" (2026-11-20, after the fourth build)

The caller heard V on this model as reading text aloud, unlike GPT Live One and the official
app. What was checked:

- Not a mode. GPT Live One (OpenClaw's own client) creates its call at the same address with
  the same session fields, and gives results to the model on the same `speakable` channel.
- Not the audio path. In the call in question the page reported one underflow in thirteen
  minutes, an output clock ratio of 1, and no delivery gaps.
- A pitch-range measurement on recordings (seven conditions, two to four takes each) could not
  tell the prompts apart: takes of the same prompt differed more than the prompts did.
- What the call itself shows: V's ordinary answers were single turns of about twenty seconds,
  finished paragraphs, one of them describing its own character in the words of its
  instructions. On GPT Live One the instructions never reached the model, so it spoke in
  OpenAI's own conversational manner; here they did, and pages of style rules (the shared
  persona's presence, style, pacing and "thinking cue" sections, and this build's list of
  particles and manner of speech) produced composed, recited answers.

Changed: the instructions begin with how to speak (a live call, never read out; one or two
sentences, about ten seconds, then stop and listen; the most important bit first), V's
character in three sentences and not to be described aloud, and of the shared persona only
who V is and how V thinks. A result is told the same way (the first sentence or two, then
wait), and a script is still said as written but in a speaking voice. The prompt went from
about 5,700 to 3,300 characters. With the real model the self-introduction went from a
twenty-second paragraph to two sentences and a question back.

Not verified by ear from here. Four recordings of the same three questions were given to the
caller: the fourth build, this one, this one on `gpt-live-1-codex`, and `gpt-live-1-codex`
with no instructions at all (what GPT Live One sounds like).

## Halting playback, and pace (2026-11-21)

- "一顿一顿", on this Candidate from the start. GPT Live's voice reaches the phone at the speed
  it plays, 20 ms at a time over the relay, and the page started playing with 120 ms in hand
  (enough for voices that arrive faster than they play). On one real call the queue ran dry
  61 times in 167 s of speech, with packets up to 0.6 s apart; on another, 56 times in 455 s.
  For this model the page now starts with 320 ms and widens by 120 ms, up to 680 ms, each time
  the queue runs dry in the middle of a reply. The cost is that much later a start of each
  reply. The media peer also counts the packets it gave up waiting for (`lost` in
  `media-stats`); it does not conceal them.
- Pace. Measured on single replies of the real model (letters per second from the first to the
  last audible frame): 5.0-6.4 with "an easy conversational pace", 5.8 on `gpt-live-1-codex`
  with the same instructions, about 5.0 with "a calm, unhurried pace, noticeably slower than
  quick chatter" (now used). The recordings given to the caller the first time had their quiet
  frames dropped by the recording script and sounded faster and more clipped than the calls.

## Wrong answers about "this year" (2026-11-21)

Asked for a team's roster "this year", V explained one from the season before. That request
is a lesson, and a lesson about something current is researched first:

- The search query was the lesson's topic as it stood. "今年…" tells a search engine nothing
  about the year; it returned last season's pages. The query now writes the year out and adds
  the month (`datedQuery`).
- What was found reached the lesson writer as the Gateway's JSON, each field wrapped as
  untrusted external content with tracking addresses, cut at 8,000 characters: about two
  results' worth of markup. The writer filled the rest from what it remembered. It now gets
  the same dated plain lines the voice models get.
- The writer was never told the date. Its input now carries `today`, and its instructions say
  that what is true now comes from the reference, newest date first, and that a gap is said to
  be a gap rather than filled from memory.

These three are in shared code and apply to every model's lessons. Search results given to
GPT Live itself also say what today is. In the same call the plain search answers (a team's
record, a correction after the caller objected) were right; only the lesson was wrong.

Re-test on the Candidate (build `6c9fdbf`, synthetic speech, one call each): the same roster
question now gets a lesson in which the player the first answer had out for the season is the
team's centre and in the starting five of its latest game; a second team's lesson gives this
season's record. Whether every name in them is right was not checked from here.

The halting playback after the wider window: 4 times the queue ran dry in 124 s of speech on
the next real call (61 in 167 s before), packets up to 0.5 s apart. The pace went back to
"an easy conversational pace": the calmer wording was judged too slow by the caller, whose
earlier "too fast" came from recordings with their pauses removed. A finished task told as a
script stopped after two sentences under the new short-turn rule; a script is now said to its
end.

## "GPT answers with much less than Doubao" (2026-11-21)

Same three questions to both models on the Candidate (synthetic speech), with the raw tool
results recorded once for the comparison and the recording removed afterwards:

- Neither model sees full text. A web search returns six passages of at most 500 characters
  each (2,000-3,000 characters in all), a memory search six passages of 500-700 characters
  (about 3,300). The 17-22 KB Doubao is handed is the same passages inside the Gateway's
  JSON: each field wrapped as external content, the addresses, and the whole list a second
  time as text.
- GPT Live was given the passages as plain dated lines, cut at 2,400 characters: the fifth and
  sixth results were lost. And since the fifth build every answer followed the short-turn
  rule: two items and "which one would you like to hear?". Doubao told four news items and
  five games; GPT Live two and three.
- Changed: the whole result is given (up to 6,000 characters), and what the caller asked to be
  looked up is told in full, an item a sentence, without stopping to ask. Short turns remain
  for conversation. Asked again, GPT Live told five news items.
- Each model still makes one lookup per question and answers from passages. Giving both the
  same cleaned, dated lines, and reading the top hits in full before answering, are shared
  changes that also touch the released Doubao path; they are not made here.

## A stronger model behind the voice: tried, and taken out (2026-11-21)

What gpt-live-1.1 is designed to lean on is hosted delegation: a Responses model with real
web search and tools that the voice model hands work to. Tried on the ChatGPT login
(`delegation: {type: "responses", ...}`): the session starts and the model delegates, but the
backend call is refused (`responses_validation_failed`, HTTP 401). It is a public-API feature,
like standby and the instructions field.

For one build the same subscription's Responses endpoint stood in for it (`web_answer`): a
model with built-in web search that reads the pages, 10-25 s an answer, given to the caller as
a second pass after the search's first look. It was more complete than the passages (both
teams' scorers where they had three players) and not checked to be right (one answer disagreed
with two direct runs of the same model).

It is removed, by the owner's decision: this integration exists so that short tasks are
answered by the call's own tools, quickly, without a backend model. A model that reads pages
for twenty seconds is the backend under another name, and long work already has its path
(`delegate_to_v`). A lookup is one tool call and one answer again.

## It explains and tells stories itself (2026-11-21)

Until here an explanation or a story was a script written by the board's model and read out by

like reading", and it used the model for its voice only. On this model the lesson tool is no
longer offered (`VOICE_GPT_LIVE_SCRIPTED_LESSONS=1` brings it back for comparison):

- The instructions say that an explanation or a story is told by the model itself, at length,
  and how (a conclusion first, a point a sentence with something concrete in it; a story acted
  out, with names). The page draws along with what it says, as it does for any answer.
- What it needs facts for is looked up first: the caller's own things from memory, today's
  world with the search. Everything else
  it is simply told to say; a delegation for such a thing is handed straight back
  (`answer_directly`, not a tool).
- A finished task is told in the model's own words as well, since no script is written.
- With the real model: an explanation of why the sky is blue began as soon as the question
  ended and ran 27 s; a bedtime story of its own ran 36 s. A script used to begin 7 s after the
  question. About 4.1-4.6 letters a second.
- Not verified: the page. Its pictures now come only from the board following the speech (the
  way ordinary answers are drawn), not from a page prepared ahead with photos for each line;
  how that looks during a two-minute story has to be seen on a phone.

## No fixed patterns; which model routes (2026-11-21)

a lookup, an explanation, each by words in the sentence). On the owner's real calls they
decided 7 of 49 tool choices (five explanations, two hang-ups) and the model the other 42; they
saved about a second each and could only be wrong by keyword, which is not how this agent is
meant to decide. They are removed. A sentence the model gives no usable choice for goes to the
agent.

### The two repairs are judged too (2026-11-23)

Two repairs behind the model were still found by word lists: a short reply that looked like a
goodbye ("拜拜", "下次聊" ...) with no hang-up delegated, a short reply that looked like a
promise ("我想想", "等我一下" ...) with nothing running, and, in the session, a caller's
sentence made only of farewell words that must not cancel a hang-up. All three lists are gone.
What V just said, the caller's last words and the last few turns are put to a model as three
yes/no questions (`createReplyJudge`): is V closing the call and does the caller want that; is
V only promising to think, look or come back; are the caller's words during a hang-up only a
goodbye. With a platform key it is one Decisions request with three predicates; without one,
the routing model answers the same three through a function call. Without either, nothing is
repaired: there is no word list to fall back to.

- The reply is judged as soon as it ends (64 characters or fewer; longer replies are not asked
  about). 2.2 s later, if nothing was delegated, nobody spoke and nothing is running: a
  goodbye (0.7 or more) ends the call, an empty promise (0.6 or more) is called out once.
- During a hang-up the caller's words are judged; unless they are only a goodbye (0.5 or
  more), the hang-up is cancelled as before. This is asked of the voice path (`keepsEnding`):
  Doubao and GPT Live One have none, so for them any speech cancels a hang-up, as released.

Measured on V, 23 invented exchanges (9 goodbyes or not, 8 promises or not, 6 sentences said
during a hang-up), each twice:

| Judge | Right | Median | p90 | Slowest |
|---|---|---|---|---|
| Decisions (`gpt-6-luna`), three predicates in one request | 46/46 | 307 ms | 411 ms | 531 ms |
| `deepseek-flash`, three booleans through a function call | 46/46 | 844 ms | 1,193 ms | 1,494 ms |

Both are well inside the 2.2 s the repairs wait anyway. On the Candidate (build `882b7ac`,

## Driven through its own page (2026-11-23)

Until now the Candidate was checked with a probe that speaks to the relay directly. This time
the Candidate's own page was opened in Chrome (phone-sized, the same link a caller uses) with
synthetic speech as its microphone: the page's capture, upload, playback, captions and board
all run as they do for a caller. Seven scripted calls on GPT Live 1.1 and one on Doubao, each
with screenshots (kept outside the repository). The browser ran first on a laptop in Shanghai
and then on the Candidate's host; the numbers below are from the host (no cross-border audio),
build `eedc14c`, measured from the end of the caller's words.

What it found, and what was changed:

- Late audio stayed late. The caller's audio is paced out to the model by the clock; when it
  arrived in a burst after a stalled connection, silence had already been sent in its place and
  the burst was that much late for the rest of the call. From the laptop, transcripts came
  1.7 s after the words early in a call and 3.9 s after them two minutes in. Frames of a pause
  are now skipped while more than 0.2 s is waiting (speech never is). Seven calls from the
  laptop then skipped 0.7-3.8 s each (`skippedMs`) and stayed within 0.22 s (`backlogMs`);
  transcripts came 1.9-2.4 s after the words throughout.
- "Wait, don't hang up" was never heard. The page hangs up when V's goodbye has played, about
  2.4 s after the hang-up is accepted, and the caller's words arrive about 2 s after they are
  said. While the caller is audibly speaking (a run of loud audio), or their turn is open or
  being judged, the page is now not told to hang up (`ending-held`, at most 12 s). On the page:
  hang-up accepted, the caller says "wait, don't hang up, I have another question", the hang-up
  is cancelled, the call goes on, a later goodbye ends it.
- A lookup promised and not made. The model said it would look at the caller's day, delegated
  nothing, and, told that nothing was running, answered that it could not see it. What the
  caller's words call for is worked out as they stop speaking; if that is a lookup or a task it
  is now made for the model and its result given to it (`promise-kept`). The reminder is left
  for when there is nothing to look up. The judge's question no longer takes "I'm listening, go
  on" for a promise (28 invented exchanges twice on the host: Decisions 56/56, median 341 ms;
  `deepseek-flash` 56/56, median 720 ms).
- A plain goodbye the model answered without delegating took 5.7 s to end the call (the 2.2 s
  wait after its reply). When the caller's own words were already read as a hang-up, the wait
  is 0.5 s.

### Pictures for what V explains itself (2026-11-23)

### The login (2026-11-23, night)

GPT Live One has no login in the voice service: the service asks the Gateway to create the
session, the Gateway presents its own ChatGPT login (which it keeps and renews) and hands the
browser a one-time secret. GPT Live 1.1 has the service as media peer, so the Candidate had been
given a copy of an access token from a developer machine; it and its source expired together
and could not be renewed ahead of time.

- The Gateway's login works for GPT Live 1.1. Read on the host by the call the Gateway's own
  GPT Live One makes (`resolveProviderAuthProfileApiKey` for provider `openai`, OAuth profiles
  only, then `resolveOpenAICodexAuthIdentity`; both are public plugin SDK calls): a token good
  for 215 hours, in 0.8-1.7 s. Written to the Candidate's login file in place of the copy, a
  GPT Live 1.1 call on the Candidate's page connected and ran as before.
- The way it is meant to run: the `v-voice-gpt-live` plugin answers `voice.product.gpt-live-auth`
  (admin scope, which the voice service's connection has) with the current token, its account
  and its expiry, and with `VOICE_GPT_LIVE_AUTH=gateway` the service asks for it instead of
  reading a file, holding it in memory ten minutes at most and never to within five minutes of
  its expiry. The agent whose login it is must be named (`VOICE_GPT_LIVE_AUTH_AGENT`, the
  service's usual agent otherwise): on a host with several agents the default has no owner and
  the read fails, as it did when tried. Not yet running: the Gateway loads this plugin from the
  released voice artifact, so the method exists only after a release and a Gateway restart.
  Until then the Candidate's file is written by hand from the Gateway's login.

## Standby

OpenAI's standby (`session.wake_policy`, `session.idle_timeout_s`,
`session.paused` / `session.resumed`, a lower standby rate) is a public-API
WebRTC feature. On the ChatGPT login a call created with either field is
answered with 201 and then never starts: media stays in "connecting" and the
sideband answers 404 (2026-11-20, each field alone and both). It is not used
here. The subscription has no per-minute rate, and a silent call is already
ended by the 120 s idle hang-up.

## Environment

- `VOICE_ENABLE_GPT_LIVE_11=1` puts the model in the phone catalog (off by default).
- `VOICE_GPT_LIVE_AUTH_FILE` names a private JSON file with the ChatGPT (Codex)
  access token and account id (`{access, accountId, expires}` or a Codex CLI
  auth file). The service only reads it; it never refreshes the login.
- `VOICE_GPT_LIVE_AUTH=gateway` takes the login from the Gateway instead (see "The login"); `VOICE_GPT_LIVE_AUTH_AGENT` names
  the agent whose login it is. Needs the `v-voice-gpt-live` plugin of this release loaded by the Gateway.
- `VOICE_GPT_LIVE_MODEL`, `VOICE_GPT_LIVE_VOICE`: optional overrides.
- `VOICE_GPT_LIVE_SCRIPTED_LESSONS=1`: lessons as scripts to read (the lesson tool), as before;
  unset, the model explains and tells stories itself.
- `VOICE_GPT_LIVE_DECISIONS_API_KEY` (an OpenAI platform key; optionally
  `VOICE_GPT_LIVE_DECISIONS_MODEL`): the quick choice for tools that take no arguments.
- `VOICE_GPT_LIVE_ROUTER_API_KEY`, `VOICE_GPT_LIVE_ROUTER_ENDPOINT`,
  `VOICE_GPT_LIVE_ROUTER_MODEL`, `VOICE_GPT_LIVE_ROUTER_TIMEOUT_MS`: the routing
  model. Without them the board's key and DeepSeek flash are used.
