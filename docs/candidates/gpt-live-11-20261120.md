# GPT Live 1.1 Candidate

Status: Candidate only. Nothing here is released; production Voice and the
Gateway are unchanged and were not restarted.

## What is in it

`gpt-live-11` is a relay model beside Doubao and Grok. The Voice service is
the WebRTC peer to GPT Live (`gpt-live-peer.mjs`, werift + Opus) and the
phone, app and page keep the existing relay socket and screen events. The
model name on the wire is `gpt-live-1.1-codex`, the default voice `sol`.

GPT Live has no function tools: it delegates, and the application works out
from the conversation what is wanted. `gpt-live-router.mjs` turns a delegation
into one call of a tool this call was given:

- fixed patterns, no model call: the time, today's agenda, an explanation, a
  farewell, a lookup that says everything it needs (news, weather, prices,
  scores) and a question about the caller's own family;
- everything else: one fast function-calling request (the board's model, or
  the one named in `VOICE_GPT_LIVE_ROUTER_*`, 3.5 s timeout) that is given the
  last turns and whether a task is running, so "再看一下" keeps its subject and
  task controls are offered only while a task runs;
- when that fails or times out: obvious lookups go to `web_search`, the rest
  to `delegate_to_v`.

The choice starts when the caller stops speaking and is used by the delegation
that follows; nothing runs before the model delegates. The session's own code
validates and authorizes the tool call; the router can never pick a tool the
caller was not given. Results go back as plain facts: search and memory results
without external-content wrappers or links.

## Instructions on the ChatGPT login

The ChatGPT (Codex) login ignores `session.instructions`. A session created
with nothing but "you are a cat, end every sentence with 喵" introduced itself
as ChatGPT, on `gpt-live-1.1-codex` and on `gpt-live-1-codex` alike
(2026-11-20). The first build of this Candidate therefore ran on OpenAI's own
prompt: it called itself ChatGPT, explained things itself instead of asking
for a lesson, and sounded like a generic assistant.

What the model does follow is the conversation it is started with. The
instructions now travel as developer messages in `initial_items`
(`gptLiveInitialItems`), in the structure OpenAI documents for gpt-live-1.1:
name and tone first, then `Backchannel policy`, `Interruption policy`,
`Delegation policy` with `Backend tools` / `Delegate to the backend when` /
`Do not delegate when`. Context appended later (`session.context.append`) is
followed too; `session.update` is refused ("Instructions cannot be updated
after initialization").

## Greeting, explain mode, hang-up

- Greeting: asked for when the call is ready (`session.context.append`,
  speakable) and again every 1.9 s, at most three times, until V speaks. It is
  withdrawn when the caller speaks first, so it is never said in place of an
  answer.
- Explain mode: "讲解 / 解释 / 讲讲 / 科普", a story, or a request for pictures
  becomes `explain_on_board`; the script comes back with the wording OpenAI
  documents for text to be read as written. Its caption is the script itself,
  as far as the voice has got, and the board follows that.
- In two of eight explanation calls the model said "好,我讲讲" and never
  delegated. When the caller's own words ask for an explanation and no
  delegation has come 2.5 s after them, the service prepares the lesson itself
  and gives the script to the session. No other tool is started without the
  model.
- A delegation can arrive before the caller's words are final. The tool call
  waits for them: the session ties a tool call to the caller's last finished
  turn and takes a later one for a change of mind (a hang-up was being
  cancelled by the caller's own goodbye).
- A reply is reported finished after its audio tail. Reported earlier, the
  tail looked like a reply that never ends and everything that waits for V to
  stop speaking waited with it (a lesson script: about 8 s).

## After the first real call on a phone (2026-11-20)

What the call showed, and what was changed for it:

- The caller's words in V's bubble, and on the board. GPT Live reports the caller's speech as it
  is spoken; the service passed those pieces on, and both the page and the board take every
  unfinished transcript for V speaking. The caller's words are now passed on once, whole, as
  the other models do.
- The board did not follow a lesson. With Doubao the script is spoken by its own text-to-speech
  and captioned as written; the board finds the script's words in the caption. Here the caption
  was the model's own text (half-width punctuation, split in two by an interruption), the board
  took it for a new reply and drew a second page from the speech, without the lesson's pictures.
  The caption of a script being read is now the script as written, advanced as far as the model's
  own text has got, and marked as a script (`V-backend-summary`). The board takes any part of the
  script being read for the same page, also when a reading that was interrupted picks up again.
  The model's text runs at most about two seconds ahead of its voice (measured on the long
  replies of that call), which is how far ahead of the voice a drawing can appear.
  On the page, a caption that grows as the script is read does not yet contain the cues further
  on, and a piece whose cue is not in the caption counted as tied to nothing and was shown at
  once; while such a caption is unfinished the page now keeps those pieces waiting
  (`withCuesToCome`). A reading whose opening the model puts differently (a sentence skipped,
  a phrase changed: seen once in the re-test) is found inside what was said and followed from
  there.
- "配上图" answered by a lesson was taken for an unkept promise to create an image: the check
  that repairs such promises sent the model a nudge to start a creation, and cleared the phone's
  audio, as the script began. A lesson with pictures now counts as the promise kept (this path
  is shared with the other models).
- A finished task was not told as a lesson. The session writes a script from the result; this
  model was given it with "tell the user this" and paraphrased it, so nothing was drawn. It is
  now given as a script to read. While the script is written (three to four seconds) the model is
  told the result is in: in the call it answered "nothing new yet" three seconds after the task
  had finished.
- Results waited for the caller to stop speaking (twenty seconds for one task, sixty-five for
  another, while people in the room talked). A result given while the caller speaks is held by the model
  itself until the caller's turn ends (measured: it began speaking at the end of the turn), so
  the service no longer holds it back.
- Memory answers. Each record was cut to 520 characters before the model saw it (Doubao receives
  the records whole): six records of about 3,000 bytes each became 2,400 characters in all.
  Records are now given at the length the search returned them (up to 1,200 characters each),
  with where each comes from and a note that a record describes the time it was written.
- A request for a story with pictures went to the agent and came back as a generated image
  after ninety seconds. Stories and requests for pictures now go to the lesson tool (a script and real
  pictures in a few seconds); a nickname transcribed as a number is kept as spoken.
- Character and voice. V on this model is written as sunny, sweet and gentle, first in the
  instructions. The timbre is the other half and cannot be judged from here: the page offers the
  model's voices (nine work on the ChatGPT login; `marin` is refused), and remembers the choice.

Re-test on the Candidate after these changes (synthetic speech through the HTTPS entry, build
`6862e94`, 20:33-20:55 CST; one call each, times after the end of the caller's speech):

| Scenario | Doubao | GPT Live 1.1 |
|---|---|---|
| A story for a child, with a named character and pictures | lesson tool +4.1 s, story begins +8.2 s | lesson tool +1.7 s, story begins +7.4 s, captioned in the script's own words; board page drawn ahead (photo, list, flow) |
| How one of the caller's own projects works, then how it is running now | not run | memory lookup +2.3 s both times; the answers say what the records cover and what they do not |
| A background task, then "just the broad picture" | not run | short result told in the model's own words; the follow-up becomes a lesson that begins +7.3 s and is read as written |
| A task result written as a script (local harness, real model, simulated task) | - | read from its first sentence, captioned as written |

Not covered by this re-test: the page itself. The probe is a relay client; that the pieces of a
lesson appear with the voice on a phone's page is covered by unit tests of the page's own
functions, not by a call on a phone.

## Compared with GPT Live One

| | GPT Live One (released) | GPT Live 1.1 (this Candidate) |
|---|---|---|
| WebRTC peer | the browser, with a session the Gateway creates | the Voice service; clients keep the relay |
| A delegation | answered by the whole V agent (median about 20 s, 2026-10-20) | one of the call's own tools in 0-1 s; only long tasks reach the agent |
| Instructions | `session.instructions` through the Gateway | developer messages in `initial_items` |
| Greeting | the Gateway appends a speakable context when the page reports audio ready | the same event, from the Voice service, retried until spoken |
| Hang-up | the Gateway host decides | `end_call`, the same as Doubao |
| Explain mode | none | lesson script and board |

The same test on `gpt-live-1-codex` suggests the released GPT Live One persona
no longer reaches the model either; that path belongs to the Gateway and is not
changed here.

## Standby

OpenAI's standby (`session.wake_policy`, `session.idle_timeout_s`,
`session.paused` / `session.resumed`, a lower standby rate) is a public-API
WebRTC feature. On the ChatGPT login a call created with either field is
answered with 201 and then never starts: media stays in "connecting" and the
sideband answers 404 (2026-11-20, each field alone and both). It is not used
here. The subscription has no per-minute rate, and a silent call is already
ended by the 120 s idle hang-up.

## Environment

- `VOICE_ENABLE_GPT_LIVE_11=1` puts the model in the phone catalog (off by default).
- `VOICE_GPT_LIVE_AUTH_FILE` names a private JSON file with the ChatGPT (Codex)
  access token and account id (`{access, accountId, expires}` or a Codex CLI
  auth file). The service only reads it; it never refreshes the login.
- `VOICE_GPT_LIVE_MODEL`, `VOICE_GPT_LIVE_VOICE`: optional overrides.
- `VOICE_GPT_LIVE_ROUTER_API_KEY`, `VOICE_GPT_LIVE_ROUTER_ENDPOINT`,
  `VOICE_GPT_LIVE_ROUTER_MODEL`, `VOICE_GPT_LIVE_ROUTER_TIMEOUT_MS`: the routing
  model. Without them the board's key and DeepSeek flash are used.

## Not verified

Real phone microphone, echo cancellation, barge-in by voice, lock screen,
headphones, the iOS app, weak networks, long calls, robots and speakers (the
model is not offered to device endpoints). The agenda answer in this build came
from the conversation record, not from a calendar query. The login file is a
copy of an access token and expires; a durable login for the Voice service is a
separate decision.
