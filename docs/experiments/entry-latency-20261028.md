## 已有诊断

三个原始样本均在 reservation 后预取 catalog/context，但 relay 到达时已过 1 秒，重复读取；后一次读取在拨号后约 3.0–3.5 秒开始，约 0.5 秒后才连接模型。候选尝试将网页准入、reservation 和 relay 合并到一条连接，保留现有实时身份检查和预取有效期。旧 iOS v1 协议保持原义，网页使用显式 v2，不能让网页误入原生事件解释器。

2026-10-28 新线上观察：菜单 12708 ms + 拨号 3742 ms，完整 16450 ms；与原始样本分列。另一次接通观察条件错误，保留为无效样本，不用于收益计算。

## 实现与兼容

`api/status` 和身份完成快照显式宣布 `webDialVersion: 2`。网页的 SeedDuplex/Grok 使用 `/api/dial?dialVersion=2`，同一连接内完成本次准入、reservation、attach。保留 live actor 检查、origin/cookie/visitor、容量限制、call owner 和工具执行前校验；没有跨拨号权限缓存，没有改动一秒准备有效期。未宣布能力的旧服务与 GPT WebRTC 保持 HTTP 路径。

v2 不接受 `nativeRuntimeVersion`；它继续接收网页原有事件和 input policy，不能进入 iOS 原生语义解释器。v1 参数与原生执行保持。reservation 与适配器接管间的 ready/audio 帧有界保留；取消会关闭连接，失败不自动发起第二次 HTTP 拨号。

本轮只改变 Web/飞书的拨号传输。现有原生 App 的 v1/HTTP 路径、机器人和音响协议未切换，**不能把本轮网页收益算成 Action Button 收益**。平台 #499、Gateway 配置和原生 binary 均不在本轮变更中。
