## 部署与独立性

- 服务器 x86_64 Linux，8vCPU、约31GiB内存；部署时 available约18GiB。与生产共用主机资源，使用独立非登录低权限用户、独立目录、独立 Node/Python/systemd 服务。Voice 服务 CPUQuota100%、MemoryMax1GiB、TasksMax128、Nice10。没有做并发容量验收。
- 根目录 `/var/lib/v-voice-candidates/speaker-stream-linux-20261018`，源代码在其 `voice/`，私有配置在 `private/`。应用监听127.0.0.1:26327，专属 HTTPS 隧道进程运行在 Linux。没有修改生产 Nginx 或已有 Cloudflare 隧道配置。
- Gateway 复用此前已隔离的 speaker-native 私有实例，Linux 本机127.0.0.1:26367，未连生产 Gateway；只复制指向该私有实例的 receipt。原生模型、ASR、Decision 均由 Linux 直接调用外部接口。没有复制或刷新生产 OAuth、个人聊天或飞书账号，私人 Gateway 的既有试验上下文也不是完整生产环境。
- Linux 本机 venv：Python3.12、sherpa-onnx1.13.8、numpy2.5.4；Node22.23.1。WeSpeaker25.31MiB与 Mac 同文件，SHA256 `f86cd6c509f331f0e20b07bd48d1b2eb7de54202643401c4e84695ac861a0e5a`。未安装全局 Python 依赖。
- 测试期间确认旧 Mac26325/26320均无活动通话，暂停本线程的 Mac流式进程及专用26368 SSH转发。Linux 的完整多人/连续会话仍正常生成真实原生PCM；通过服务器本机 Gateway、没有向 Mac 回传识人。测试后按记录恢复旧候选组件，不影响本 Linux 入口的独立运行。
- 公网 HTTPS 是本候选专用 Quick Tunnel 临时地址，带独立随机入口令牌。令牌/真实地址/环境文件/收据不进 Git；无 Cookie访问API返回401。隧道重建会改变地址，不能视为正式域名或长期SLA。

## 速度与资源

同一3.624秒合成问题，服务端测试器经候选 HTTPS/WSS 路径发送音频，发言结束到收到第一包真实原生回答 PCM 为计时口径。排除缓存“我上网查一下”，不含拨号与浏览器/扬声器播放延迟。对照均在 Linux 私有实例中运行，不是拨打生产。

首次3次流式：3.179 / 6.047 / 5.587秒；后两次额外查网。原生对照：2.554 / 3.937 / 2.523秒；中间一次查网。原生第三轮首次因反复登录触发429未发音频，保留失败后复用Cookie重试，不把重试当作原始3/3稳定成功。

Linux 声线一秒窗口20次本机测量：请求往返中位29ms、P95 32ms、worker冷启动239ms。跨父子合成声线相似度0.176。这个推理耗时不包含约一秒声音积累，也不证明真人身份精度。Voice进程组实际观测内存约150–170MiB，CPU限制下仍可运行；单次轻量观察不代表峰值或并发上限。

最终连续会话三问：6.657 / 2.661 / 2.684秒，均有原生回答；首轮仍查网，后两轮复用人物连接。前一轮相同测试为6.182 / 2.621 / 2.681秒。Linux 没有出现“识人一定很慢”的结论，稳定轮次约2.6–2.7秒，长尾仍来自查网、最终语义判断、首次人物准备/保守重放。

补强旁话判断后，按相同入口和语料切换候选本身做串行/流式对照，测试完恢复默认流式。每组3次成功样本如下：

| Linux 路线 | 三次真实原生回答，秒 | 中位数 |
|---|---|---:|
| 旧串行输入门控 | 9.526 / 8.099 / 8.408 | 8.408 s |
| 最终流式多人 | 6.059 / 5.764 / 2.835 | 5.764 s |
| 原生直连对照 | 2.554 / 3.937 / 2.523 | 2.554 s |

流式成功样本中位数比串行低31.4%。串行/流式各有两次非必要查网，原生有一次，因此不能只把差值归因于识人或服务器CPU。流式没有查网的一次为2.835秒。不是所有轮次都接近原生直连。

串行切回流式后第一次测试撞到受控重启窗口，Cloudflare返回HTML错误页、未发音频；保留该失败，等就绪后重试得到6.059秒。最终流式是3次成功/4次尝试，不能写成无失败3/3。此前原生第三轮、首轮多人和首轮连续测试的429均为批量脚本重复登录导致，修复脚本复用Cookie后重试，未放宽服务端保护。

旧 Mac测试2.99/3.17秒仅为历史参考，不用于证明纯硬件提速，网络、模型随机工具选择和测量位置均可能影响差值。

## 多人效果与修复

同一108.936秒、7段合成父子语料。孩子角色由另一个成人合成音色扮演，不能当作真实儿童录音验收。

Linux 初次完整轮 `linux-quality-r2` 的原始 passed 只代表旧传输判断：它正确区分父子、回复孩子、分别给父子建议、进入exclusive并过滤父亲，但错误回应了“递杯子”旁话，效果判为失败。保留该收据与原生字幕/PCM。

ASR 漏掉被叫人的名字时，Decision 曾将实物协作当作对V的请求。补强语义判断：人际生活协作且无明确请求V提供信息/提醒/可用控制时保持安静；明确向V问能力问题仍可回应。没有用测试句关键词硬拦截实际音频。

最终 `linux-quality-final` 无路由错误、输入完整、真实原生音频返回，以下八项逐项为true：

1. 两位声线、姓名及adult/child角色保持独立。
2. 孩子自己的月亮问题只回应孩子。
3. 递杯子旁话保持安静。
4. 共同建议选择父子两人，实际原生回答分别称呼双方。
5. “只跟十二聊”进入exclusive且目标为孩子。
6. 父亲旁话withheld、modelCalled=false，无该句native提交。
7. 孩子故事请求仍只回应孩子。
8. 故事请求后确有真实原生PCM，而非只返回路由决定。

首次孩子角色确认的回答延迟10.140秒；共同对象变更8.908秒；已知孩子继续故事3.408秒。切换轮次仍慢，没有将稳定轮次数字套到所有情况。实际月亮解释有简化、故事有虚构内容，本文只验收路由和表达对象，不宣称科学准确性或听感完美。

新增“漏掉姓名的递杯子旁话”及“直接问V拿东西能力”文本案例，Linux真实 Decisions API13/13通过，已知本批Decision费用$0.0026774；另有Mac侧首次intro超时失败保留，失败不自动放行。
