# Speaker + Decision + 原生语音：候选验证（2026-10-16）

## 结论与交付

候选已经接到 Voice 的真实 H5 产品，入口为 `http://127.0.0.1:26320/`，模型选择支持小何和 GPT Live。输出保留各自原生语音与工具链，不再由外部文字模型撰写回复再送 TTS。无需注册声纹或手动校准。代码基于 `b109f52` 的独立分支 `codex/volc-speaker-modes`，没有合入或上线。

当前实现可试用，但不建议替换线上默认路径：输入门控增加约整句音频时长的等待；匿名 ASR 仍会把两个人合并或将一个人拆成多个 Speaker。最终 GPT 合成多人测试通过关键行为，小何本轮多人识别未通过。不能称为已完成真人父子或多场景验收。

## 对照环境与测量口径

- 线上只读核实：H5 release 为 `a88fd3a315528acba25a1b7cdfdc2c20723e8c66`，Gateway pinned runtime 为 `/opt/openclaw-2026.9.1-v/openclaw`，GPT 是 `gpt-live-1-codex`，小何是 SeedDuplex `1.2.6.1/xiaohe`。
- 原生对照在独立私有 Gateway 和本地产品中执行，保持原生传输、模型和产品工具路径。**不是拨打生产服务得到的线上测速。**本地产品基于较新的 Voice candidate 代码，包含后续任务控制指引；私有环境无个人记忆、飞书频道和生产工具凭据，因此也不是完整生产上下文的逐字节镜像。
- 旧 candidate `26319` 保持原样：ASR + 匿名 Speaker → Seed 2.1 Lite 决策并生成回复 → 小何流式 TTS。
- 新 candidate：同样的匿名 ASR → `openai/gpt-6-luna-decisions` 做 typed choices → 原始音频与人物上下文 → 原生小何/GPT Live。实际回包模型 `openai/gpt-6-luna-decisions-20261006`。
- 单句全部使用同一段 3.624 秒的合成“天空为什么是蓝色的，请一句话回答”音频；排除拨号和缓存问候耗时，计时起点为合成音频的真实发言结束点，不以 ASR 给出的结束时间替代。
- 多人全部使用同一段 108.936 秒合成父子音频，共 7 段原始发言，ASR 可能再拆句。包括自我介绍、孩子提问、递杯子旁话、分别建议、专注十二、父亲旁话、孩子故事。

## 速度结果

| 链路 | 3 次结果，秒 | 中位数 | 终点 |
|---|---|---:|---|
| 原生 GPT 对照 | 1.150 / 0.771 / 2.031 | 1.150 s | 浏览器入站音频首次实际能量 |
| Speaker + Decision + GPT | 7.224 / 6.758 / 7.077 | 7.077 s | 同上 |
| 原生小何对照 | 8.985 / 4.746 / 5.155 | 5.155 s | 服务端首个原生生成 PCM 包，排除缓存工具提示语 |
| Speaker + Decision + 小何 | 10.086 / 11.250 / 9.431 | 10.086 s | 同上 |
| 旧文字候选 + 小何 TTS | 2.965 / 2.803 / 2.745 | 2.803 s | 服务端首个 MP3 包 |

GPT 新链路第 2 次在已出声后被测试者提前结束，保留首次音频时间，不计作完整回答内容通过；第 1、3 次均保留完整正确回答。另有完整多人 GPT 通话证明最终对象组合修复后的整条链路。

这些终点不能混在一起计算统一排名：GPT 是浏览器音频能量，小何是服务端 PCM，旧候选是压缩音频首包；后两者还不包含浏览器缓冲与扬声器延迟。小何首包的 120ms 播放缓冲未算入表内。

小何原生在部分单句中发起工具/后端，影响延迟并造成重复回答。若把缓存“我上网查一下”也算出声，原生对照首包为 8.985 / 1.190 / 1.277 秒；新链路为 10.086 / 6.506 / 9.431 秒。它们不代表真正开始回答。保留同一产品工具策略，没有为跑分快而删工具或伪造结果。

Decision 的最终 11 例文本回归全部通过，正常响应约 0.47–0.90 秒，已知该批费用 $0.0020743。此前出现 2.5 秒超时，最终候选允许最多 5 秒；失败不放行音频，也不自动改用文字生成。这个模型调用时间不是端到端响应时间。原生语音、ASR/TTS 总费用没有统一账单回执，不能由此推算整轮实际金额。

主要代价是：等 ASR 的最终分人结果 + Decision + 原生音频按 1 倍速重放 + 原生端再次判断结束和回答。Decision 更快仍无法消掉整句重放。当前实现没有取得提速收益。

## 多人效果

| 行为 | 原生对照 | 旧文字候选 | 新 GPT 最终轮 | 新小何完整轮 |
|---|---|---|---|---|
| 无注册开始接话 | 两模型均可 | 可 | 可，实际原生音频 | 可，实际原生音频 |
| 自动区分父子 | 无主机 Speaker 记录 | 出现同一孩子拆成 B/C | 本轮 A/B 正确 | 初段父子误合成 A，失败 |
| 孩子自己的问题回应孩子 | 依赖原生理解 | 对匿名 C 回答，身份未关联 | 明确选择 B/十二 | 初段误归父亲，失败 |
| 递杯子的旁话不回答 | 两模型都插话 | 安静 | 安静，未提交该句音频 | 本轮错误回应，失败 |
| 分别给父子建议 | GPT 原生可；小何泛化共同建议 | 选择父子并分别回复 | 选择 A+B，实际分别回复 | 只有 A 被识别；后端文字能提父子，不能算路由通过 |
| 切到十二后过滤父亲 | GPT 原生仍回应父亲；小何没有独立父亲答复，但后续将两句合并转写，无法证明过滤 | 已知目标声线被拦 | exclusive，父亲句 modelCalled=false，无原生重放 | 切换时目标尚未被识别，未进入 exclusive，失败 |
| 十二继续问故事 | 两模型可讲 | 可讲儿童故事 | 明确回应 B，实际原生故事 | 后段终于识别 B，能讲故事，但此前排他失败仍保留 |

新 GPT 首轮曾把孩子问题标成回答父亲。逐人概率打分改成“明确选择回应对象组合”后，在最终同音频完整轮中修复。旧错误收据保留，不覆盖成通过。

小何所用的上游匿名 ASR 在完整轮中把孩子的自我介绍和问题都标为父亲声线，而且漏掉“递杯子”句前的称呼。当前层没有足够可靠依据纠正声线与身份，不能靠让模型猜名字就宣称解决。相同 ASR 也在旧候选和其他轮次把同一孩子拆成 B/C；这个问题不是原生语音输出模型本身的差异。

小何与 GPT 都在真实 H5 界面里收到实际播放音频，小何浏览器验证还保留了原生工具提示、原生回答和后端补充的完整字幕。没有把音频字节、模型已返回或某个静态 demo 当作完整声音体验验收；本轮没有真人麦克风、外放回声或听感盲测。

## 修复与回归

- 匿名首句不再发送只有一个选项的非法姓名 Choice；不要求唤醒词恰好被 ASR 写出来。
- GPT legacy `session.context.append` 按 UTF-8 限额分块，等待确认后再送音频；迟到确认、旧轮判断、关闭后音频不会续播。
- 对象组合直接选择；姓名只从真实文本候选关联，明确自我介绍与猜测分开。
- 被过滤者不会触发网页本地打断；小何 native 输入有静音保活。过滤服务关闭不会回退到未过滤原始音频。
- 验证脚本补上真实产品的心跳。此前约 58 秒断开的长测试是脚本缺心跳，不能归因于模型失败；保留旧收据。
- `npm test`：453/453；新增 `test:speaker-native`：10/10。测试覆盖实际音频不泄漏、排他对象、安静/多人选择、陈旧判断取消、音频窗口边界、后台播放不被旁人打断等。

## 生产边界与后续

生产 H5 PID 始终为 `783762`，Gateway PID 为 `782397`，均 active；配置 SHA256 前后同为 `62b16fc453dd8d5fecf8b39f90591df4510af525ce19e117c1101cca84c3da66`，release symlink 未变。没有写生产配置、刷新生产 OAuth、重启线上服务或切换版本。私有 Gateway 使用独立端口/状态，只有已有短期 OpenAI access token，不复制真实 refresh token、个人聊天或飞书账号。

建议保持线上原生默认，候选继续研究两个瓶颈：可靠且可修订的会话说话人身份；避免整句重放的流式输入策略。后者需要明确权衡旁话是否可以先到模型、哪些原生协议允许输入缓冲提交/丢弃，再按同语料验证，不宜直接让所有声音透传后仍宣称已过滤。

尚未覆盖：真人父子、同声抢话、电视/远场、不同麦克风、手机 AEC、长通话，以及陌生名字先指定后开口的绑定。当前多人数上限 5，每句临时音频最多 20 秒，每通候选 180 秒。
