# GPT Live 原生多人能力直连测试（2026-10-16）

## 结论

原生 GPT Live 可以根据对话中的自我介绍自然接话，也观察到按人物称呼、儿童化比喻与忽略旁聊的正面表现。但本轮无法稳定仅凭声音维持人物身份，不能据此移除外部 Speaker；“只和十二聊”在独立观察窗口中出现明确失败。父子同问时也没有稳定展示不同表达方式。

因此原生理解与稳定身份路由应分别验收。当前证据支持继续用原生模型负责自然语音与表达，同时研究低延迟地补充人物信息；不支持直接用提示词替换严格目标过滤。现有产品链路、线上版本与服务均未修改。

## 测试边界

直接使用与当前产品相同的 OAuth 原生 `gpt-live-1-codex` / `sol` / WebRTC。服务端直接向已知的 ChatGPT Codex realtime 接口交换 SDP，浏览器发送连续原生音轨。不经过 Voice 产品、Gateway consult、外部 ASR、Speaker、Decision，也不向模型发送转写或人物标签。只在启动时给简短的多人聊天、姓名关联、成人/孩子表达、旁聊和排他对象指引；姓名与关系都通过输入音频介绍。

仅从已有私有候选数据库只读获取短期 OAuth access token 到进程内存，不复制 refresh token、不刷新生产授权、不更改线上或现有 candidate 的服务和默认链路。该次测试不是公有项目 Key 版本 `gpt-live-1` 的验证：本机未发现可用项目 Key，不能把两个 API 版本的行为视为完全相同。

先尝试了直接 WebSocket：本机 Codex OAuth 与私有候选 OAuth 均能完成握手，但在启动时收到 `forbidden / Voice session access denied`。因此改用已在产品中跑通的原生 WebRTC 协议；这个错误不能独自确定是模型、账号还是传输准入限制。

## 同文案换声线盲测

两个固定合成声线分别介绍自己为天意（父亲）和十二（孩子），随后用完全相同的文字询问当前说话人的名字。每个声线的提问音频生成一次后重复使用，包含同一声线连续提问，避免只靠轮流出现猜身份。第二个独立会话交换介绍顺序。

| 会话 | 正确 | 叫错 | 不确定 |
|---|---:|---:|---:|
| 先天意后十二，6 次提问 | 3 | 1 | 2 |
| 先十二后天意，6 次提问 | 2 | 0 | 4 |
| 合计 12 次 | 5 | 1 | 6 |

将天意的同音转写“天忆”按正确口头姓名计算，未因汉字差异判错。错误样本是父亲声线被答为十二；同一段父亲音频也曾得到“不确定”和正确姓名。输入转写没有明显漏收，最后一段在第一轮被原生系统拆成两个用户 turn。数字是本轮小样本描述，不是通用准确率。

两轮均正常结束，无模型错误事件，收到原生解码 PCM 与 `session.closed`；后端模型用量为空。12 次短句从原始音频结束到浏览器实际解码音频能量的中位约 1.502 秒，包含 ScriptProcessor 分块带来的观测延迟。与旧候选的测试问题、观测实现不同，不据此计算严格提速倍数。

## 对话行为测试

初轮固定等待 9 秒再发送下一段。原生模型曾对相同月亮问题分别称呼十二和天意，给十二的回答使用手电筒照球的比喻。之后的递杯子旁聊没有独立回答，口头专注后父亲问题的观察窗口没有新语音，孩子随后提问得到回答。

但初轮完整回答跨过了下一段输入的开始；脚本当时按“收到 turn.done 时的当前片段”归属字幕，出现负延迟及晚到字幕，不能直接把 `turns[].reply` 当作该输入的正确回答。原始 `events` 时间线保留了实际关系。旁聊与专注指令被合并转写，专注后的父亲和孩子问题也被合成一个用户 turn，不能据此证明严格按声线过滤。

追加 `behavior_clean`：对预期回答的输入等待完整字幕结束且实际输出音频安静至少 1.2 秒，最多等待 25 秒；旁聊单独观察 12 秒，专注后的父亲提问单独观察 20 秒。初轮结果保留，不覆盖。

复测完整结束、没有模型错误或委派事件，得到以下结果：

| 项目 | 复测观察 | 判断 |
|---|---|---|
| 自我介绍 | 分别问候天意与十二 | 能理解明确说出的姓名与关系 |
| 相同问题按成人/孩子分别表达 | 都用了“月亮变胖变瘦”式解释，且没有持续称呼对象 | 未证明稳定差异化表达 |
| 递杯子旁聊 | 独立 12 秒无回答、无有效输出音频 | 此样本成功忽略 |
| 口头专注 | 明确说“好的，我只跟十二聊” | 仅为口头确认 |
| 专注后父亲提问 | 约 1.399 秒后开始回答；在孩子下一次提问前已完整答完 | 排他对象控制明确失败 |
| 孩子继续提问 | 正常回答 | 此样本正常接话 |

4 个会话均取得 `session.closed`，原生回执音频时长总计 431.6 秒，无后端模型用量。8 段 TTS 样本用量总计 157 text_words。未取得 OAuth 语音/TTS 的统一金额账单，不把公有 API 的每分钟价格冒充实际支付金额。

## 证据与复验

工具：`lab/speaker-native/verify-gpt-native-speakers.mjs`。26324 仅为内部合成输入测试工具，正常用户仍使用现有产品 26320。工具不请求麦克风权限、不录制人的语音。默认最多启动 3 个会话，单次样本流程有时长上限；本轮前三个会话结束后重启该临时工具追加一轮复测。

```sh
VOICE_CREDENTIAL_ENV_FILE=/absolute/path/to/private.env \
  node --dns-result-order=ipv4first lab/speaker-native/verify-gpt-native-speakers.mjs --prepare
node --dns-result-order=ipv4first lab/speaker-native/verify-gpt-native-speakers.mjs
```

忽略目录 `artifacts/speaker-native/gpt-native-speakers/` 保留每轮 JSON、原生解码 PCM/WAV、合成输入 WAV/MP3、TTS 用量和 identity-summary.json。JSON 仅含合成对话；凭据不进入产物。传输完成不代表质量通过。

输入 A 使用合成男声，B 使用合成女声扮演孩子，并非真实儿童声线。尚未验证真人父子、多人重叠、电视/远场、AEC、不同设备、长期稳定性与实际外放听感。本轮不授权合入或上线。

官方资料：[GPT Live 启动与连接](https://developers.openai.com/api/docs/guides/live)、[原生聊天提示](https://developers.openai.com/api/docs/guides/live-prompting)、[会话与上下文更新](https://developers.openai.com/api/docs/guides/live-conversations)。这些资料描述公有 API，不能替代本轮 OAuth 协议的实际结果，也没有建立稳定多人声纹识别的保证。
