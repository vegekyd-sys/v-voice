# 共享终端行为

2026-10-24 候选；未合入、未上线、未做真实设备音频验收。

Web 与 iOS 的 direct-voice 入口，以及 StackChan/xiaozhi、原生音响入口，均由 `lab/realtime-direct-tools/session.mjs` 执行对话、搜索、任务控制、进度播报与结果交付。模型可用性、服务器绑定的账号权限不因终端统一而扩大。GPT 自身传输适配保持原样；本次修复的是共享 direct-voice 引擎内的 phone/speaker 行为分叉。

## 收敛内容

- 自然搜索接话由同一 `searchAcknowledgment` 设置控制，默认生产入口启用。不再为设备单独播放固定的开始提示，也不再按 phone/speaker 选择工具描述。
- 原生双工由模型及是否使用多人输入路由决定，不由终端名决定。多人输入路由继续负责准入、人物切换、打断与输出门控。
- 所有终端沿用相同的任务阶段、真实进展、等待节奏、插话保护、结果归属与挂断后后台继续规则。
- `lookup-recovery.mjs` 统一慢查询的有限 PCM 提示、失败后沉默、已有结果未开口的恢复。设备适配层只读取 `awaitingToolAnswer` 保持播放窗口，不再决定查询话术。多人模式不注入可能交付给错误人物的恢复语音。
- 完整结果和语音摘要沿用同一个处理流程；无内容屏幕的终端不声明“已在屏幕显示”，也不自动扩大发送授权。

## 终端层可保留的差异

采样率、Opus/PCM、回声与近场处理、原生播放回执、唤醒后的空闲窗口、音量、屏幕展示能力、摄像头、舵机及 Reaction。设备的 `inputPolicy` 由可信服务端配置明确传入；不修改现场配置。原生 UI 事件包装属于协议兼容适配，不决定对话策略。

新增对话或任务能力必须在共享引擎实现，并扩展 `session.test.mjs` 的 Web/iOS/StackChan/speaker 参数化回归；不要新增终端专用的搜索、任务或交付策略。设备端点测试继续以真实本机 HTTP/WebSocket 和 xiaozhi 编解码覆盖适配器，模型和 Gateway 用确定性替身，不能冒充真实通话。
