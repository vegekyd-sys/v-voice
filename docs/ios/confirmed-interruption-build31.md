## 问题与行为

用户的 2026-10-24 00:39–00:42 真机通话中，有六次在播放队列非空时主动暂停 1.8–2.6 秒，附近没有新的模型说话开始事件。本地 RMS/过零率连续 140 ms 即获取播放暂停，未确认探测随后由 1.8 秒超时及 600 ms generation grace 恢复。声源具体是残余回声、环境声还是短语，未通过录音确定。

build 31 将本地音量/过零率检测改为插话候选。只有近期候选，加上高置信度的本地声学人声分类或服务 `playback.hold`，才能暂停。

本地执行器使用 Apple SoundAnalysis `.version1`，500 ms 分析窗口、50% 重叠，服务下发的人声阈值默认 0.9（原生接受范围 0.8–1）。处理 post-AEC PCM，串行后台队列最多积压六个 20 ms 帧；超过 350 ms 的结果拒绝使用。没有语音转写、录音或新增网络服务。设备无法及时分类时仍可使用服务开始信号。依据：[Apple SNClassifySoundRequest](https://developer.apple.com/documentation/soundanalysis/snclassifysoundrequest)。

服务与本地证据的先后两种顺序均支持，候选在 2 秒后过期，服务可在 100–5000 ms 范围内下发窗口。旧服务缺字段时使用兼容默认。Web assisted 没有该原生声学分类能力时使用服务确认路径，旧 courtesy/provider 模式保持其协议行为。

识别完成后仍等待明确处置：忽略插话则恢复原样保留的音频，新回复则淘汰旧尾音。没有关闭麦克风、取消模型打断或增加固定高音量门槛。本地高置信度人声可以先行暂停，不必等待网络；它仍然是可逆让出，模型决定忽略还是替换。没有声学确证时，回退路径的响应仍包含网络与模型检测延迟。

真机测试还暴露出挂断时 ping 完成回调重复调用导致的 continuation 崩溃。为该跨线程回调增加一次性完成保护，并覆盖成功后失败、失败后成功等重复完成情况。
