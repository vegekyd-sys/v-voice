# iOS build 32：轻声插话响应修复候选

状态：PR #106 候选，未合入、未部署生产服务。build 31 和 build 30 签名安装包保留回退；正式版本登记不变。

## 反馈与证据

用户在 build 31 反馈“现在打断有点困难”。01:26–01:29 的手机记录中，五次暂停都跟随服务端语音开始信号，本地快速通道没有触发。旧版未记录被拒绝的分类结果，因此无法仅凭该通话日志区分人声置信度不足与本地音量门槛拒绝。

代码中，本地高置信度分类还要求 RMS ≥0.035（或噪声底的三倍）且连续 140 ms。受控的轻声输入逐帧 RMS 全部低于 0.035，即使分类明确为人声，build 31 也不能在本地获取暂停。这是本次修复的可复现缺陷。

## 行为

确认人声的辅助证据改为独立、有界的策略：默认 `speechRMS=0.006`、`speechOnsetMS=60`，零交叉率约束保留，短暂音节间隙让证据递减而不立即清零。服务可配置范围分别为 0.001–0.1、20–500 ms；旧服务缺字段时采用兼容默认。原能量门槛仍为旧客户端保留。

本地人声置信度仍需 ≥0.9，结果仍需新鲜；服务确认与本地证据两种到达顺序均支持。单纯能量不获取暂停。忽略后恢复、识别后等新回复、旧尾音淘汰继续保留。禁用播放探测时清空证据，避免把前一次输入用于新输出。只增加每五秒的数值分类峰值诊断，不记录原始麦克风或转写内容。

## 验证

- Swift 核心 45 项、Web/服务 50 项通过；共享服务到原生集成 4 项通过，含服务策略热更新与识别后不续播旧回答。
- 实体手机本地分类：固定合成语音缩至原幅度的 15%，只送前一秒；808 ms 获取暂停，峰值分类置信度 0.930。逐帧最高 RMS 低于旧门槛，不以放宽测试延迟断言获得通过。
- 实体手机真实扬声器→麦克风→VPIO 回声路径：16 秒、808 帧、0 次自我打断，峰值人声置信度 0.836。麦克风仅在内存分析，没有上传或保存。
- 完整线上模型通话：同一生产 CallCoordinator、真实模型、硬件播放；轻声输入为固定合成语音原幅度的 15%。连续 16.020 秒渲染，0 次误暂停、0 ms 有缓存游标停滞；本地在约 817 ms 获取暂停（轮询观测 837 ms），人声置信度 0.922、结果年龄 7 ms；模型正确改答，正常挂断。签名安装结果另见 JSON 登记。

上述是同一 iPhone 上的受控验证，合成语音不等同于真人远场/双人重叠验收；用户是否觉得好打断仍单独验收。独立网络延迟问题不在本次修复结论中。
