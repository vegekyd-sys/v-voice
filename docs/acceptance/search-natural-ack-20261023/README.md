## 实现

- 新增独立候选开关 `VOICE_SEARCH_ACK=model`，默认关闭；旧 `VOICE_TOOL_START_NOTICE=model` 不会重新开启电话接话。模型根据当前问题组织简短回应，同轮立即发起 web_search / memory_search。没有预制语句、外加 TTS、辅助模型、等待音频播完的定时器。
- 工具描述及完整通话指令明确区分“可先接话”和“必须查完才能回答事实”。不改工具参数、账户或权限。完整多人策略之后再次明确查询接话规则，因为仅在前段提示/单工具场景通过并不能推广到完整目录。
- 搜索输出只有在整个 envelope 严格等价于重复 JSON 的 text/details 时才去重。保留所有结果、引用、路径、分数、警告与 debug；错误/附加字段/多内容块/非搜索工具保持原样。真实零命中诊断输出 729 → 269 bytes；完整合成工具结果分别 487 → 172、475 → 166 bytes。没有据此声称模型延迟已降低。
- `tool.search-metrics` 只记录数值型耗时、命中数、字节数和是否去重；不新增 query、结果或原始 debug 日志。可与既有 ASR、工具和 TTS-start 事件关联定位后续延迟。

## 实验结果与失败记录

使用火山 TTS 合成男性提问、真实 SeedDuplex 1.2.6.1 接口；工具返回采用固定内容与 1 秒网页 / 7.8 秒记忆延迟。完整集成测试运行 Candidate 的 `createDirectVoiceService`、全部现有电话工具与多人提示。没有浏览器扬声器、手机麦克风或真实数据库检索验收。

- 旧接话提示：网页 1336 ms 首音频，单次工具正常；记忆仍 9997 ms 才首音频，失败。
- 只加强总提示：网页两次 1315 / 1350 ms；记忆两次仍 9979 / 9937 ms，失败。
- 单独工具加描述：记忆 1211 ms 首音频并完成结果；放回完整目录后两次仍 9948 / 9899 ms，失败，未当作通过。
- 最终完整记忆方案：两次 1285 / 1260 ms 首音频，1776 / 1503 ms 启动工具，各调用一次，均随后播报实际 fixture 答案。
- 完整网页候选：1344 ms 首音频，1833 ms 启动工具，调用一次并回答。完整静默网页对照尝试额外后台委派，被 fixture 阻止，最终答案失败；该条不用于最终答案速度比较。
- 最终记忆插话：1214 ms 先接话，随后合成输入“等一下，不用查了，告诉我一加一等于几”，产生清音事件，回答新问题。旧检索稍后返回后没有播报旧答案。没有据此声称真实手机打断延迟已验收。

所有首音频数字为合成输入文件发送完 → Candidate 收到首 PCM，含输入尾部静音和网络波动；小样本证明可行性，不代表 P95 或稳定性保证。自然接话增加了部分工具决策时间，最终答案没有被证明更快。目的为提前确认听到了请求；记忆检索根因仍需 Gateway 独立诊断。

实际音频与原始事件留在本机私有 `Documents/Codex/voice-search-latency-20261023`，Git 仅提交脱敏指标。试听样本按接收时间重建等待间隔，不是手机录音。计费试验为 17 次短模型会话、3 条合成输入；账单金额未读取，不能报实际费用。

## 验证与边界

- Node 全套 736 项通过；最终指令改动后的服务、去重与日志定向回归 100 项通过。
- `scripts/eval-search-ack.mjs` 需显式 `VOICE_SEARCH_EVAL_ALLOW_PAID=1`、已有服务端凭据、私有 synthetic `study.json`，默认测试不会触发付费。每批最多 8 条，每条通话上限 30 秒；工具执行严格由 fixture 接管，非 fixture Gateway 请求拒绝。

### 发布前提示一致性修正

最初接话版在正确采样率的整链多人对照中，姓名检查为 3/4，线上基线为 4/4；电视干扰时还出现不应有的接话，因此未发布。将多人规则简单放回最后可抑制背景接话，却使记忆接话再次失效。最终调整为：统一 session 工具声明与 prompt 中工具目录的搜索说明；只保留一条简短接话指令，明确只适用于向 V 发起的搜索，并让原有 NATIVE_DUPLEX_POLICY 保持最后优先级。该版记忆查询实测 1219 ms 首音频、1439 ms 发起工具、正常回答结果。最终多人对照另附 release-regression.json。

第一轮旧音频以 24 kHz 数据误按 16 kHz 注入，语速/音高失真；该轮已排除，不用于回归结论。有效测试先将已知 24 kHz 火山 TTS 样本重采样到 16 kHz，再按 20 ms 实时发送；原本为 16 kHz 的搜索和插话样本不再重采样。
