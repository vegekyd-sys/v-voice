## 已确认的失效边界

真实豆包 provider + 合成麦克风 + 受控工具复现：委派报告后，搜索等待 25 秒；报告先完成并经过 `speech_text_buffer.commit`；用户继续口述，ASR 与模型回应均正常；旧搜索随后返回，正确 `call_id` 的 `role=tool` 已实际送入 WebSocket，但直到 70 秒观察结束没有新文本、音频或协议错误。

这证明原生调用的续接位置在后续播报/回合之后不能继续依赖。没有证明单独一个 SayHello 就是全部根因，也没有证明用户早上所有静默都同因。此前已经收到的用户话语不能归因成麦克风没捕获。

## 改动

- 正常、未被替换的工具结果仍聚合后走原生续答。
- 确认的新用户文字或主机固定播报会标记等待中的原生批次。迟到结果加入有界 QA 上下文，并通过主机的现有完整结果呈现接口交付；不伪造新用户提问、不重新执行工具。
- 只有实际屏幕确认后才说“已经放到屏幕上”；未确认时说“屏幕正在同步”。空闲门同时检查用户发言、模型生成、浏览器播放和最近用户时间。排队后再有新话语会退休旧提示；明确取消会清队列并过滤旧结果。
- 记录输入帧数、帧龄、麦克风轨道和 AudioContext 状态。结合 ASR、工具交付和响应日志区分采集暂停与模型没有输出；不录制用户原始音频。
