## 本仓库改动

1. 沿用 #169：同一个请求中只消费一次刚完成的服务端准入，超过 1 秒重新核验；不跨请求缓存成员资格。
2. 飞书只读工具的 accessor 在接通时只捕获已验证 actor，不启动 CLI。真正调用工具时仍先检查实时工具权限，再校验安装 guard、app、user，之后才能执行只读命令；取消会终止探测，身份不匹配/未授权直接失败，无个人账号回退。模型可能看到专用工具后收到未授权错误，之后仍可按原规则使用当前会话能力或委派；并不授予缺失的飞书授权。
3. 模型与辅助打断 ASR 同时连接，仍等两者成功后才发 `ready`。失败关闭两条连接，provider 原有有界优雅关闭保持。没有跳过打断准备，没有更改音频、播放、分类器或音量阈值。
4. 记录 actor-reader、model-ready、speech-control 的固定阶段和 monotonic `elapsedMs`；白名单日志不保存错误原文、凭证、工具输出或音频。后续可区分模型和辅助检测的耗时。

## 平台准入独立优化

实际 owning source 是平台的 `lab/feishu-voice-policy.mjs`，不在 Voice 复制它。该候选并行读取 chat 信息和第一页成员，合并尚未返回的相同只读请求；已经完成/失败的结果立即丢弃。每个 actor 的成员判断与配置、路由、owner 和工具授权仍分别执行。

每次 policy 请求按生产行为新建飞书客户端，使用真实 API，将线上 policy 源码与候选源码在同一主机交替执行。只有 chat/member 读取是真实的，后续路由依赖为 fixture，未经过候选 Gateway dispatch；不能记作平台完整上线验收。

## 验证和发布边界

在本地运行真实 Voice preparation 实现，依赖延迟固定为目录 650、上下文 800、模型 600、辅助 ASR 200ms，线上 `b4ed555` 源码对候选各 5 次。就绪中位数 **1605→1405ms**。这是可复现的并行调度收益，不是线上模型实测；见 [controlled-replay.json](controlled-replay.json) 和 `scripts/candidate/connect-preparation-benchmark.mjs`。

相邻测试覆盖两条握手都启动且任一未完成时不能 ready、辅助连接失败时清理、撤权/错账号/取消不执行真实读取，以及 Web/iOS/StackChan/speaker 的共享行为。验证计数与打包校验在 [validation.json](validation.json) 登记。

Voice 只使用原有 Gateway 接口，无协议或共享配置变更。平台部分单独完成隔离 VLab 的实际模块 overlay 与授权回归；没有抢占共享集成 lease。两部分都未合入/上线。本轮未做真实付费模型拨号、手机音频或实体 Action Button 测量。按 build 32 基线的实机播放/打断，以及组合后的按下到可对话计时仍待验，不能宣布用户的约 5 秒已经解决。
