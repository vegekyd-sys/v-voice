# 插话后等待新回答：2026-10-23

## 问题和处理

旧版在原生识别结束后启动 1800 ms 恢复计时器（生成未结束时再加 600 ms），另有 12/15 秒硬上限。用户已经插话说完、下一回答尚未生成时，旧队列会恢复播放，随后被新回答突然切走。

Web 和 iOS build 22 增加“已识别、等待原生判断”的保持状态。保留原队列但不随计时器恢复；模型明确忽略电视/旁聊时按既有 responseId 恢复；接受新回答后沿用旧 response retirement / scoped clear 丢弃尾巴。空识别和失败识别不新增长保持，后来的失败也不能释放仍待处理的已识别插话。没有新模型、姓名规则或额外 speaker 链路，Gateway 不变。

本次为 Voice 内部控制事件增加可选 recognized 布尔值和播放修复，使用既有接口与权限，在本地 Candidate 验收。
