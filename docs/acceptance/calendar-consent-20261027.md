# 日程请求授权与服务选择候选

状态：本地候选，未合入、未部署、未做真实通话验收。

## 问题与范围

最近通话出现了用户已明确要求创建飞书日程，语音仍再次询问写入授权的情况。同一绑定会话的两次日历任务还分别选用了企业微信查询和创建；后一次创建调用被企业微信权限错误拒绝。之后明确限定飞书的任务成功创建并回读。这里只记录故障类型，原始通话、账号、日程和生产日志不入库。

候选统一 GPT Live、小何、Grok 的语音规则：用户对具体动作的直接请求构成该范围内的授权，交后台不新增授权步骤；委派保留原要求及服务、对象、时间和修正。缺参数澄清缺项，真实 OAuth/工具权限拒绝仍保留。绑定飞书会话的个人日程默认使用已授权的飞书账号，不能用企业微信替代，也不能混用两者的错误。

只改 Voice 提示内容及已有后台请求中的规则文本，没有修改 Gateway RPC、账号绑定、工具权限检查或客户端协议。使用本地隔离测试及打包验证，不占用共享 VLab。Web/iOS/机器人/音响使用共同服务规则，不涉及原生或固件修改。
