## 外部联系人的根因

飞书官方 [机器人支持外部群和外部用户单聊](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group) 的“OpenAPI 调用限制”明确说明：对外共享机器人无法获取外部用户的 `user_access_token`。机器人可在获准的消息与群组场景中获取外部用户的 `open_id`，但无法据此查询外部用户通讯录信息。

当前 Voice 的网页 OAuth 和客户端 SDK 最终都需要交换用户授权码，再用服务端取得的身份签名请求 Gateway。外部用户在飞书授权层被拒绝，因此无法走到当前的已验证账号分支。为机器人打开“允许外部单聊”不解决这一限制；`requestAccess`/`requestAuthCode` 也不能作为绕过方案。

这里需要区分三件事：

- 机器人知道是哪一个外部用户发来了飞书消息：消息事件可以提供可信的发送人标识。
- 当前电话浏览器属于该外部用户：现有 OAuth 无法完成这一证明，普通群链接或私聊链接本身也不能证明打开者是谁。
- 以外部用户的个人凭证操作飞书：对外共享自建应用不能取得该用户凭证，识别身份也不会补出其个人日历等权限。

Public/临时来电可以继续对话，但未取得账号身份。用户口述姓名只能作为对话称呼，不能据此开放历史、个人工具或将回复回写到原飞书会话。

## 建议的外部身份接入方式（尚未实现）

采用飞书内的一次点击确认，把可信聊天身份绑定到发起连接的浏览器。保留已经取消的手工验证码流程为已废弃状态。实现需要 Voice 与平台两侧配合：

1. Voice 为当前浏览器创建短时、一次性的连接请求，绑定目标应用与会话以及浏览器持有的私有证明。
2. 在对应飞书会话中展示明确说明用途的确认卡片。身份只来自飞书验签通过的交互回调操作人；不能来自 URL、浏览器输入、姓名或群成员猜测。
3. Gateway 重新检查该操作人是否属于目标会话，以及现有文字入口的准入和权限；只把确认结果交给原始请求浏览器。拒绝重放、超时、被转发链接、其他浏览器和错误会话。
4. 成功后显示已连接的外部账号及会话，建立可撤销的设备绑定。工具执行继续沿用该操作人的文字渠道权限；个人凭证不因这次身份确认而产生。

卡片的具体投递、回调关联和浏览器持有证明需要在独立平台 PR 与 Voice Candidate 中实现，并用外部真实账号完成验收。当前没有以静态私聊链接冒充登录，也没有重新上线复制验证码。
