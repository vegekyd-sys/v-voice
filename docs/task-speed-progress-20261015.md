# 后台任务耗时与过程反馈候选

本轮从同日生产文字记录和服务现场定位问题，只收集已有文本，未录制用户音频。原始对话、来源资料、回放请求与完整模型输出保留在私有证据目录，不进入仓库。

## 查明的问题

- 一个 17 字的人物合作问题被包装成 16,850 字符的后台请求。固定指引、重复历史和媒体/长文呈现规则同时进入普通问答。
- 原人物查询约 60 秒后已结束；期间的进度追问又排了新的 consult，其中一次恢复了数小时前已取消的另一话题，随后耗时约 56 秒。另一次状态追问排队约 37 秒。不能把这些时间全归因于模型生成。
- 实际检索里有约 26 秒的工作区递归扫描，以及另一查询约 21 秒的记忆工具等待。缩短提示词不会消除这些工具成本；候选只要求优先定向读取命中的来源，尚未证明真实工具步骤减少。
- 公开进度依赖模型主动产生可分类 commentary；原有中间事件不携带可显示正文，工具执行本身几乎不可见。
- 原生后台曾返回带前置句的具体摘要，旧解析器未识别配对标题，前端随后口播了泛化内容。

## 此仓库改动

1. 原生与 relay 共用当前目标边界及简短回答约束；历史作为资料，不作为待办。普通问答避免扩写报告；用户明确要详细报告时保留完整交付。
2. 从原 runId 的真实 lifecycle/tool 事件生成固定阶段标签，公开 commentary 单独显示；不转发工具参数、结果或推理。阶段返回只说明工具返回，不声称任务成功。
3. 三种模型的网页路径都能接收阶段文字。状态包含持续时间；恢复 presentation 时保留起点。进度不创建新任务，不在用户讲话时强制播报，取消/挂断后不恢复旧页面任务。
4. 原生交付优先采用后台实际准备的摘要，兼容摘要标题前的前置句，完整正文保留。精简媒体/结果说明，媒体任务仍沿同一付费任务跟进。

重复历史与固定长提示词的根本缩减位于平台仓库的 `codex/voice-consult-scope-20261015`，本仓库没有复制 Gateway/Worker 实现。完整 GPT Live 改善依赖两边代码配合。

## 验证与边界

- 本仓库完整 Node 回归通过；新增覆盖真实工具阶段到 relay/presentation、无外发授权时的原生可见进度、外来 run/session、迟到事件、取消、计时恢复、摘要保真。
- Codex 内置浏览器本地事件回放，1280×720 和 390×844：受理→检索→公开阶段事实→取消可见；移动视口无横向溢出，取消按钮在视口内，控制台无错误。该页面只回放脱敏阶段，不调用麦克风或模型。
- 四种真实请求的同模型来源回放，共 8 次调用（第二轮）：包装从 16.9–17.4k 字符降到约 2.8–3.4k，模型回答中位耗时 4.67→2.93 秒。两组读取完全相同的各场景原资料，补入原来相关的前序话语；未执行新的工具或外部动作。
- 第一轮使用了过宽的混合资料，只作诊断；后续针对短追问继续试验。全部试验共 24 次现有 DeepSeek V4 Flash 调用，以 5 美元会话上限做保守预留，最终约 3.94 美元预留；provider 配置成本返回零，不能当作真实账单或免费调用。
- 即使收紧规则，最终两例仍偶发生成额外完整方案。故只能报告输入缩减与所测回答耗时，不能报告全链路速度改善、质量不下降、所有进度追问不再排队或真人通话验收通过。

当前为候选，未合并、未部署。平台完整集成须走共享 VLab；真人语音还需验证阶段播报、插话、话题切换及最终结果的实际可听性。发布时保留既有权限、任务控制、挂断接续和原环境回滚边界。
