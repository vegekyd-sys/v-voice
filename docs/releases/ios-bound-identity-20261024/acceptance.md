# iOS 绑定同步飞书身份 — Candidate

旧绑定保存了飞书 tenant/open ID，但没有姓名。动态会话在 App 请求时从设备凭证恢复身份，缺失的姓名因此无法进入模型来电人上下文。另外，现有 App 会复用同一 URL 的已保存凭证；此前不同账号在同一会话生成相同 URL，重新绑定可能继续使用旧身份。

本次在已验证浏览器生成绑定时，为同账号、同会话的有效设备凭证补齐 `displayName` / `userId`。不修改 actor ID、授权范围、有效期或已撤销凭证。新 URL 按会话和已验证账号区分；同账号姓名变化不改变 URL。旧 URL、旧 Cookie 和旧凭证继续兼容。

此改动属于 Voice 设备绑定与来电人资料保存，继续调用既有 Gateway admission 和 actor-scoped 接口，不修改 Gateway 的身份判定、工具权限或跨服务协议。在本任务独立 Candidate 验证；不写共享 VLab 配置或重启 Gateway。生产和实体手机尚未验收。

验证：

- 全套 Voice 测试 898 项通过；包括真实 HTTP 和 WebSocket 接口的 mock 上游回归。
- 生产形状旧凭证在更新资料后，Grok / 小何 reserve 和 GPT caller context 均收到服务端验证的姓名；客户端伪造姓名/账号不被使用。
- 旧 Cookie、重启后持久化、有效期不延长、已撤销凭证不恢复、跨会话拒绝、旧入口映射保持有效。
- 访客 → 飞书、Alice → Bob 生成不同的原生目的地址，Cookie 名称与现有 App 的验证规则一致；各自恢复自己的身份。
- 网页构建及 iOS H5 shell 同步通过。没有修改 Swift、音频、打断或固件；没有真实付费拨号。

旧用户需在飞书页面打开一次「iOS App」生成绑定，再在 App「验证并绑定」。此前仅有账号 ID 的绑定无法凭空补出飞书未返回的姓名。


## 日历直查与 iOS 内容提示（同一 Candidate 的 .2 更新）

生产通话的工具记录显示，10 月 24 日 11:50 的“查周一日历”先调用记忆，再交给后端；没有 `feishu_calendar` 调用。代码原因是所有 `sessionBound` 会话统一移除了本地飞书快捷工具。另发现服务 PATH 缺少 CLI 所在 Node 目录，旧 Voice CLI 配置也不符合现有凭据隔离要求。没有关闭隔离检查或复制凭据。

现在仅对服务端验证的 appId/openId 使用 V 已安装的 `lark-cli --user` 分账号入口：先核对 guard 应用及实际 whoami，再提供日历/只读工具。每次查询重新请求签名的 Gateway 工具目录并要求 exec 能力仍有效，CLI router 每次再次检查该用户实际凭据；未知账号、错误应用、授权失效均不回退到个人账号。浏览器传来的 toolIdentity 不被采用。此路径只改 Voice，复用现有 Gateway 接口和已安装身份路由；共享 VLab 的既有 Gateway 接口需做只读集成核对，未自动合入或上线。

iOS 原因是旧文档读取失败写入的提示没有随 callID 清除，异步失败也缺少原通话归属检查。修复后新通话清空旧提示，旧请求成功或失败均不能污染下一通。修复进入可下载 H5 shell，不需要重新发 TestFlight 原生版本。

验证：

- 全套 Voice 903 项通过，覆盖 Grok/小何直接调用、通话中撤回 exec 后拒绝、未认证来电/无凭据/错误应用禁止快捷通道、浏览器伪造 toolIdentity 无效、进程取消和退出确认。
- V 生产主机以现有 Voice 服务用户执行候选 reader，使用已有本人授权，真实查询 2026-10-26：CLI ok=true，身份核对 151ms，日历查询 681ms，无后端模型调用。结果只留成功和耗时，不保存日历正文。这不是实体 iPhone 语音验收。
- iOS Simulator 真实 WKWebView 回归：修复前复现旧提示跨通话残留，修复后通过；补测旧请求在新通话建立后才返回错误，提示仍不出现。H5ShellTests 最终 9/9 通过。
- 测试过程曾遇到一项既有说话人标签时序断言失败，单项复测及最终全组均通过；新增晚到请求测试的 JS 返回函数问题已改为显式 void 返回，最终通过。没有掩盖失败。
- 未发起付费语音拨号；真实手机、真实语音模型的工具选择、未授权的其他账号均未声称验收完成。
