# Candidate 原生挂断缺失告别语音修复

2026-10-22；只更新 Candidate，未合入或上线。运行版本 `voice-seeduplex-duplex.20261022.7`，冻结代码 `09b533dee6ce11fcc8c0e7dfaab3dc6e52928fce`。

## 实际问题

真人反馈最后没能自动挂断。只读核对该通话末尾：模型已经识别了明确告别，并成功执行 `end_call`；之后观察窗口内 20 秒没有新增输出音频，通话仍未结束。系统要求有告别音频、完成事件及真实播放结束确认才关闭，因而在没有告别音频时无限等待。没有证据把它归因于没听懂告别、浏览器静音或网络断开，也尚未确定上游为什么没有后续语音。

## 改动

- 仍由豆包原生语义决定是否调用 `end_call`，没有增加关键词挂断或人物判断链路。
- 原生电话已成功接受挂断后，先等待原生正常告别。如果 2 秒没有收到新的告别音频，用现有原生 TTS 补发简短告别；收到音频及完成事件后，仍等待浏览器实际播放结束确认。
- 补发的 TTS 也一直没有音频时，再等待 10 秒后按已确认的挂断请求关闭，记录 `farewell-unavailable`，不伪造“语音播完”。用户正在继续发言时先让话，不强行截断新问题。
- 新问题、明确继续输入、原输出被打断或通话关闭会撤销挂断及其计时器。已播完的正常告别不会再补一句。旧回答尾包和不匹配的完成/播放确认不能取得告别的完成资格。
- 挂断只结束电话；已经接纳的后台任务保持运行。普通插话、多人姓名上下文和背景声音策略不变，未重新启用 Speaker / Decision 链路。

## 验证

主回归 **710/710**；Speaker 回归 **95/95**。服务回归模拟了缺失上游告别、补发 TTS 仍无音频、重复工具后挂断、旧音频尾包、正常告别不重复补发、继续提问、文字继续输入、正在说话、通话关闭和后台任务存活。缺失音频分支是服务故障模拟，不能冒充再次复现了原真人长通话。

真实豆包 1.2.6.1 + Candidate HTTPS/WebSocket + 浏览器实际 AudioWorklet 播放完成三轮：

| 场景 | 实际结果 |
| --- | --- |
| 连续四次报时工具调用后告别 | 4 次 `current_time`、1 次 `end_call`；有实际告别 PCM、完成事件和浏览器 `playback.drained`，自动回到可拨号页面；告别输入结束后约 8.0 秒发出播放结束确认 |
| 告别后立即继续问时间 | 调用 `current_time` 并回答；未调用 `end_call`，回答后仍在通话；测试结束后由探针主动清理 |
| 普通告别 | 1 次 `end_call`；有实际告别语音及匹配播放确认，自动回到可拨号页面；告别输入结束后约 6.1 秒发出播放结束确认 |

三轮服务端均有关闭记录。真实三轮中原生模型正常发出了告别语音；补发及无音频关闭分支由服务故障模拟覆盖，不声称它们已在真实上游故障中再次触发。输入为既有合成语音，未新增物理手机或麦克风验收，也没有完整重放原来的真人长通话及其后台委派。

两次自动挂断均出现一条 HTTP 409 控制台记录，页面已正常回到拨号，随后重拨也成功。没有采集该请求路径，不把原因定为某个具体接口，也不把这轮记成“零网络错误”。
