# SeedDuplex 全双工电话候选

2026-10-22；独立分支 `codex/seeduplex-barge-in`。Candidate only，尚未合入或发布正式服。

## 行为与适用范围

电话默认经过识人、独立 ASR、整句语义放行，再向原生语音模型输入。已获准回答期间，新话进入预听通道，主通道收到静音，因而限制了 SeedDuplex 本身的持续听说、端点和抗干扰能力。

候选通过 `VOICE_PHONE_INPUT_POLICY=native` 选择豆包电话的连续原生收音。默认配置仍为 `speaker`；`?inputPolicy=speaker` 保留原多人识人对照，Grok、GPT Live、硬件音箱、Gateway/Worker 契约和入口账号权限不变。原生路径不提供原多人模式的姓名/人物气泡，不能声称两套人物能力已合并。

浏览器仅做可恢复的播放暂停，不据音量取消模型、工具或后台任务：经过浏览器 AEC/NS 的连续语音可以让播放器先让话；短脉冲、直流和高过零率噪声不取得暂停。暂停保留精确的未播放 PCM。模型若不产生替代回答，原回答恢复；模型的新回答到达时，以 response ID 淘汰旧队列和旧尾包。持续未确认声音和识别停滞均有有界恢复。句中继续发言在第一包回复到达前也持续跟踪，400ms 内的字间空隙不重新计算起声，防止抢答从抖动缓冲中漏出。短插话还会等待正在生成的旧播报结束并让出原生识别边界，避免安静后固定计时直接恢复旧声。

原生 ASR 起声本身不再不可逆地清空回答；真实取消事件仍会清音。识别失败会解除语音活动状态。新用户话轮为下一段字幕建立新行，避免被打断、没有 final 的旧字幕被下一答案覆写到旧位置。

## 验证口径

- 本地 Node 回归 664/664；speaker-native 回归 95/95。
- 真实豆包 1.2.6.1 + 真实服务端 + 公网 HTTPS + 浏览器 AudioWorklet 播放，输入是本机合成语音，未使用真人录音。
- 自动音频验证使用专用 Playwright 浏览器，便于注入合成麦克风并在实际输出节点取样；Codex 内置浏览器用于本人私有入口和最终人工试用。没有因缺少名为 browser 的 skill 而跳过内置浏览器。
- 插话检查必须同时满足：实际输出停声、新问题正确回答、停声后到替代答案前无旧音频恢复。仅第一次暂停时间不足以通过。
- 噪声/附和/模拟电视/旁聊检查是否保留原回答；句中 900ms 停顿检查实际扬声器输出，而不是把模型提前生成但未播放的音频包误算为抢答。
- 另验工具真实调用/结果、同页挂断重拨和新 voiceSessionId。

这些是合成音频及浏览器证据，不代表物理 iPhone 的麦克风、外放回声、真实电视混音或真人主观听感。多人同声和极轻声仍需真实环境验收。候选不自动授权合入或上线。
