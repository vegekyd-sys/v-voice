# SeedDuplex 全双工电话候选

2026-10-22；独立分支 `codex/seeduplex-barge-in`。Candidate only，尚未合入或发布正式服。

## 行为与适用范围

电话默认经过识人、独立 ASR、整句语义放行，再向原生语音模型输入。已获准回答期间，新话进入预听通道，主通道收到静音，因而限制了 SeedDuplex 本身的持续听说、端点和抗干扰能力。

候选通过 `VOICE_PHONE_INPUT_POLICY=native` 选择豆包电话的连续原生收音。默认配置仍为 `speaker`；`?inputPolicy=speaker` 保留原多人识人对照，Grok、GPT Live、硬件音箱、Gateway/Worker 契约和入口账号权限不变。原生路径不提供原多人模式的姓名/人物气泡，不能声称两套人物能力已合并。

浏览器仅做可恢复的播放暂停，不据音量取消模型、工具或后台任务：经过浏览器 AEC/NS 的连续语音可以让播放器先让话；短脉冲、直流和高过零率噪声不取得暂停。暂停保留精确的未播放 PCM。模型若不产生替代回答，原回答恢复；模型的新回答到达时，以 response ID 淘汰旧队列和旧尾包。持续未确认声音和识别停滞均有有界恢复。句中继续发言在第一包回复到达前也持续跟踪，400ms 内的字间空隙不重新计算起声，防止抢答从抖动缓冲中漏出。未确认的附和暂停有较短上限，避免“嗯”后长时间静音。原生模型识别滞后时，额外的流式 ASR 仅检测“等一下、先停、别说了”等明确停声前缀，淘汰当前回答的旧音频；不会放行普通问题、改变任务或权限、取消后台工作，也不阻塞主路连续收音。延迟识别必须匹配发声当时的 response ID，不能取消后来新问题的答案。该通道由 VOICE_NATIVE_INTERRUPT_ASR=1 显式启用，默认关闭，并增加一条独立 ASR 的用量。

原生 ASR 起声本身不再不可逆地清空回答；真实取消事件仍会清音。识别失败会解除语音活动状态。新用户话轮为下一段字幕建立新行，避免被打断、没有 final 的旧字幕被下一答案覆写到旧位置。

## 验证口径

- 本地 Node 回归 683/683；speaker-native 回归 95/95。
- 真实豆包 1.2.6.1 + 真实服务端 + 公网 HTTPS + 浏览器 AudioWorklet 播放，输入是本机合成语音，未使用真人录音。
- 自动音频验证使用专用 Playwright 浏览器，便于注入合成麦克风并在实际输出节点取样；Codex 内置浏览器用于本人私有入口和最终人工试用。没有因缺少名为 browser 的 skill 而跳过内置浏览器。
- 插话检查必须同时满足：实际输出停声、新问题正确回答、停声后到替代答案前无旧音频恢复。仅第一次暂停时间不足以通过。
- 噪声/附和/模拟电视/旁聊检查是否保留原回答；句中 900ms 停顿检查实际扬声器输出，而不是把模型提前生成但未播放的音频包误算为抢答。
- 另验工具真实调用/结果、同页挂断重拨和新 voiceSessionId。

这些是合成音频及浏览器证据，不代表物理 iPhone 的麦克风、外放回声、真实电视混音或真人主观听感。多人同声和极轻声仍需真实环境验收。候选不自动授权合入或上线。

## 运行隔离与回退

专用 Candidate 目录、电话服务、端口、私有入口凭据和日志；凭据始终在服务器私有环境，原始测试音频、完整转写与浏览器资料不提交 Git。沿用既有 Gateway 连接和个人入口绑定，测试没有重启 Gateway 或正式 Voice、没有变更生产配置、没有发送消息或创建新工具权限。

回退可在同一候选入口显式选择 `inputPolicy=speaker`；完整回退为停止自有 Candidate、恢复其保留的基线运行目录。生产版本和原有其他 Candidate 不受本候选切换影响。

## 已完成的真实模型/浏览器证据

- 同一合成故事/插话的原识人路径对照：从插话输入开始到清音为 9587ms；仅持续输入的原生基线为 3298ms。这两个数是公网客户端收到清音事件的时间。
- Chromium 候选实际输出节点测量：长句插话约 172ms 停声；暂停到新答案开始之间，旧语音可听样本为零，正确回答 2+3=5。短句“等一下，先停”两轮约 154–158ms 进入暂停，旧声音没有恢复，模型回复“好，我停下了”。数字是单轮合成音频样本，不是分位数或物理 iPhone 扬声器延迟。
- 12 项 Chromium 检查通过：短噪声不暂停/不清音/持续播报；附和不破坏原回答/恢复原回答/不另答；句中停顿并继续后无提前可听回复/完整问题得到标题；真实 current_time 调用/结果；同页重拨新 voiceSessionId/真实音频。
- 另一音色模拟电视播报、对旁人的话：均未替换原回答，原语音恢复。期间可能暂时让话，不能描述成任何背景人声都完全无影响。

## 火山 TTS 三档对照（2026-10-22）

本轮只增加实验脚本、评分器及证据，没有修改或重启 Candidate / 正式电话服务，没有合入或部署。主实验 6 组、两条实际路径共 12 个隔离通话实例，每组 2 句介绍和 8 个探针；另保留最初一组试跑，共 14 个通话实例。使用火山 `seed-tts-2.0` 生成 38 个音频素材，回执累计 1176 text_words。生成后的同一批 PCM 同步送入两条路径，没有按各模型分别生成样本。

三档在看到回答前按音色风格固定：低沉男声＋轻亮女声；大壹＋Vivi 的日常男女声；Vivi＋清新女声的相近女声。每个音色有两句同文校准素材。现有 Speaker embedding 的跨人余弦均值分别为 0.420、0.281、0.727，日常组在这个指标上比明显组分得更开；这是样本描述，不是独立的真人听感验收，也没有按回答得分重选音色。

原生路径使用冻结 Candidate 的豆包 1.2.6.1，持续收音，不实例化 Speaker，也没有额外停声 ASR。Speaker 对照直接加载正式 release `0d0b3d96` 的 production factory，保留声纹、流式 ASR、Decision、lookahead、音频放行；关键配置与运行中的正式服务核对一致。两条路径共用合成测试上下文；Gateway 为拒绝外部调用的 stub，未向真实个人会话、工具或飞书发请求。对照是隔离实例运行的已上线源码，不是直接拨打正式电话。

每组的 8 个探针为识人 4 次、颜色喜好 2 次、根据个人周末计划给建议 2 次。重复同一句问题，并安排同一人连续发言；另将日常组声音与姓名绑定反过来，避免只按轮流顺序猜人。只有收到实际回复 PCM 才能判对。上游 ASR 缺少 question_id 时，使用同连接最近 8 秒内的 completed ASR 与 response_id 关联；源音频窗口中的精确残句也允许归属。找不到归属的回答不能靠时间窗口判对。评分器另验延迟回复、未交付预生成回复、电视转写、ASR 残句和合并声纹等情况，7 项测试通过。

| 场景 | 豆包原生：正确回答 | 现有 Speaker：正确回答 |
| --- | ---: | ---: |
| 明显差异：低沉男声＋轻亮女声 | 8/8（识人 4/4） | 3/8（识人 2/4） |
| 日常男女声（统一计数复测） | 8/8（识人 4/4） | 5/8（识人 4/4） |
| 日常男女声（声音与名字互换） | 6/8（识人 2/4） | 2/8（识人 1/4） |
| 相近女声：Vivi＋清新女声 | 0/8（识人 0/4） | 3/8（识人 2/4） |
| 日常双人＋持续电视 | 8/8（识人 4/4） | 0/8（识人 0/4） |
| 日常双人＋噪声、旁聊和短撞击 | 8/8（识人 4/4） | 4/8（识人 2/4） |

“识人”列是最终说出的名字是否正确；Speaker 的显式声纹编号另计，不能用回答信息缺失反推声纹识别失败。主实验各组双方收到的实际 PCM SHA-256 均与语料一致，无掉入关闭连接的输入字节。首轮试跑为原生 8/8、Speaker 4/8；旧记录只校验投送字节，因此原始结果及音频单独保留，统一计数复测纳入主实验，没有删除首轮来选择结果。

日常两人原生能力值得继续沿简单路径验证，但这批小样本还不能证明稳定替代 Speaker：名字互换组前两次叫反；相近女声组在介绍时正确确认名字和喜好，后续 8 次却整组绑定反了。相近组 Speaker 则把两人的声纹都编号为 local0，它的少量答对不代表成功分出了两个人。

首轮日常干净组中，Speaker 声纹编号与对照音频保持一致，但出现第二人介绍只把尾句送入原生模型、个人信息遗漏等问题。源码还会随人物 profile 切换 bridge、仅携带最近六条获准历史；这与个人信息丢失的现象相符，尚不能单凭对照就定为唯一根因。

电视组是持续广播覆盖提问，另有“等一下、先停”电视剧台词；逐句实测信噪比约 2.4–10.5 dB。噪声组有约 3 / 10 dB 连续噪声、已介绍人物对旁人的话和短撞击。原生这两组均 8/8，没有额外回应背景内容；Speaker 电视组 0/8 并要求重说，噪声旁聊组 4/8。这里仅证明数字混音进入真实模型后的表现，不证明手机外放、回声消除或真人重叠说话已验收。

下一步仍留在 Candidate：先用这批音频做原生整条电话与当前停声旁路的对照，并验证最小的人名绑定确认；保留现有 Speaker 切回方式，暂不添加另一套判人模型或自动切换生产。原生口头叫对名字不等于已有稳定人物 ID、姓名气泡、锁定人物或身份权限。现有 Candidate 的额外 ASR 遇到电视“先停”是否误触发，本轮没有验证，不能把上表的原生结果当作整链已通过。
