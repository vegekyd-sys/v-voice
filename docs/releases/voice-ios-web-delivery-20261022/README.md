## Device Hub 验收环境冲突

随后查得 [Apple Device Hub 文档](https://developer.apple.com/documentation/xcode/interacting-with-your-app-in-device-hub) 明确说明：操作物理设备的屏幕共享期间，普通 App 无法使用摄像头／麦克风，可能记录静音；系统电话／FaceTime 等高优先级 App 则会停止镜像。上述两次零信号复现均在本轮开启的真机 View Screen 期间发生，与该限制吻合。屏幕共享已经停止，当前等待停止共享后 build 10 的真人对话回执，再判断恢复。

这属于强相关的验收环境解释，尚未由停止共享后的双向对话确认。不能据此直接将 build 12 标为接受，也不能把蓝牙切换无效写成设备或新壳故障已确诊。不为恢复麦克风随意绕过原生 AEC、切换通话 owner 或增加模型调用。

今后真机语音验收先停止 Device Hub 的 Screen Sharing，再由人操作按键并听验；只读设备中有界采集信号／上传计数和服务端因果元数据。需要视觉取证时先结束语音，再短时开镜像；模拟器可继续镜像，但其 I/O 不代表真机 Voice Processing。新增两个无模型信号回归测试覆盖 8/16/24/48 kHz 非零输入转换和数字静音的完整帧，均通过。
