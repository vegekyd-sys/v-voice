# iPhone 候选验收脚本：长句延迟

使用之前的私人候选链接，在 iPhone Safari 刷新一次。首页更新日志应显示 `voice-mobile-turn.20261021.5`。正式入口不参与本次测试。

先在相对安静的地方做 1–4，再在平时的嘈杂环境做 5–6。正常语速，不必刻意放慢。每次听完回答，在 1–2 秒内接下一句，以覆盖连续对话。全程约 3–5 分钟。

| 步骤 | 照着说或操作 | 需要观察的结果 |
| --- | --- | --- |
| 1. 接通 | 拨号，说：“V，听得见我说话吗？” | 能接通并回复。第一句不作为长句提速的判断依据。 |
| 2. 长句问答 | 等它回答完，接着说：“请你用一句话解释一下，为什么在同一天里，早上和晚上的天空会变成红色，而中午却经常是蓝色的？” | 从最后一个字说完，到听到第一声有效回答，大致记是 2 秒以内、2–5 秒，还是超过 5 秒。回答应涵盖整个问题；不能只抢答前半句。 |
| 3. 自然接话 | 说：“原来是这样，这个解释还挺有意思的，我以前一直没想明白。” | 能自然接话，整句不应误标“只听不答”。不能重复播放刚才的旧回答。 |
| 4. 真实查询 | 说：“请你查一下今天上海的天气，告诉我最高和最低温度，以及出门散步需不需要带伞。” | 有真实查询提示和最终结果。分别感受“多久开始回应”和“多久查完”，不要把查网耗时与重放等待混在一起。 |
| 5. 嘈杂与打断 | 在平时的嘈杂环境，请它讲一个小故事；讲到中间时说：“V，先停一下，改用一句话告诉我冬天呼气为什么会有白雾。” | 背景声不应不断把故事或查询打断；你明确插话后应切到新问题，不应继续播放旧故事或同时出现两路声音。记下新问题说完后的等待感。 |
| 6. 同页重拨 | 挂断，不刷新，直接重拨。先说“V，听得见吗”，回答后再问一次步骤 2 的长句。 | 第二通也能正常采集、播放和回答，不能出现第二通完全无声。 |

遇到问题不用连续重说。记下步骤编号和大约时间即可；重复会引入新的话轮，影响定位。若有系统电话打入，等来电结束后再说一句“V，现在继续”，并在反馈中注明发生来电。

反馈可以直接复制填写：

```text
测试时间：
步骤 2 等待：2 秒以内 / 2–5 秒 / 超过 5 秒
步骤 3：自然接话 / 只听不答 / 重复旧回答
步骤 4：实际查到结果 / 只说会查 / 没回应
步骤 5：正常切换 / 被背景声打断 / 不停旧回答 / 两路声音
步骤 6：正常 / 无声 / 接不通
其他：系统来电、网络切换，以及出现问题的大约时间
```

预听暂存的声音、字幕和工具，在语义确认前均不交付。角色或回应对象不兼容、预听失败、超时或达到限额时仍保守回退，因此本次不承诺所有话轮都低于两秒。真实手机、回声、混音和系统来电表现须以这次实际测试为准。
