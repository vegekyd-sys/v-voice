# TV 与 iOS 共用的通话体验

2026-10-26，本地重做候选。此前 `daead21` 只打通了功能；原生工具条、网页重复控件和粗糙的小态不再作为体验基线。

## 设计依据

按 [更新指南](UPDATE-GUIDE.md) 和 [iOS 灵动岛](ios/ISLAND.md) 的当前决定实现：小态 V + 单一状态图标；中态 Reaction、真实波形和必要通话控制；对话与方案仍由完整 H5 阅读。保留同一个通话 owner、同一个 WebView 和同一个头像 DOM，不另做 Android 对话页。

沿用 iOS `IslandCallSurface.swift` 的丁香紫 `#d6c2ed`、波形亮色 `#eadcf7`、玫瑰色 `#c96385`；岛底色 `#111014`。字体沿用 H5 的 Avenir Next / PingFang SC / system-ui，TV 上由 Android sans 回退。中态标题 18 CSS px、辅助文字 12 px、按钮 40–48 px；全页对话 20 px。焦点使用紫色轮廓，禁用与静音均有对应语义，不只变颜色。

| 状态 | 内容与操作 | TV 窗口 |
| --- | --- | --- |
| 首页入口 / 小态 | V + 电话、麦克风、播放或文档图标；确定进入中态，有方案时进入同一通话全文 | 144×48 dp |
| 中态待机 | 现有头像、“和 V 说话”、拨号；设置入口与收起；本地替身明确标注 | 420×156 dp |
| 中态通话 | 现有 Reaction、24 根实测波形、挂断；下排静音、展开对话/查看方案、收起 | 420×156 dp |
| 完整页面 | 共用响应式 H5、当前会话对话、报告阅读器；顶部单一收起按钮 | 屏幕减去边距 |

返回按完整页 → 中态 → 小态 → 退出逐级收起。Home 结束通话并释放页面。进入不自动拨号，展开/收起不重拨。遥控方向键由 H5 按实际控件位置导航，原生只转发按键。方案阅读时上下滚动正文，返回先关闭阅读器。

## 共用实现与窗口合同

- `ui/call-ui.jsx` 负责中、小态的布局与控件，`styles.css` 在 TV 模式下调整布局；普通手机布局不变。
- 原来的同一个 `#avatar` 在中态缩小，全页放大。由现有 decode-before-swap、Reaction 与实际 displayed 回执管理，不把 selected 当成 displayed。
- `tv-host.mjs` 的版本 1 合同保持兼容，新增 `layout`、有界焦点名、`reading`、`hasDocument`、无原始音频的 meter source/peak。`setLayout` 在 TV 壳里提出窗口尺寸请求，原生完成尺寸变化后调用 `commitLayout`，随后才恢复网页布局与焦点，避免先聚焦造成边缘裁切。
- Android 只有一个透明 WebView，没有第二排通话按钮。原生负责可信来源、音频权限、窗口尺寸、遥控和生命周期。私有入口选择移到闲时遥控 Menu，不输出 URL、不自动拨号。
- 方案到达不抢占中态；“查看方案”进入现有内容阅读器。页面状态与内容归属来自现有共享服务。

## 波形与播放

Relay 从实际输出 AudioWorklet 后端与输入 MediaStream 分接只读 analyser；GPT WebRTC 复用已有播放/输入 analyser。暂停、静音或无法播放时不给出虚假的输出能量。只保留 24 个量化音量值，不记录声音。

量化与 iOS `IslandPresentation.swift` 相同：约 100 ms 窗口、快起短回落、固定 `pow(rms / 0.24, 0.75)` 映射、实际输出优先、静音忽略输入；超过 350 ms 的采样断档重置，450 ms 无新采样归零。电视页面按 10 Hz 读数更新，减少动态效果时关闭补间。

本地音频验收发现 Grok 原有音频事件遗漏 response ID，而完成回执包含 ID，导致首段等待完成的音频不能释放。修复在共用 provider 补传事件/当前 response ID；回归覆盖真实 Grok bridge → 实际序列化 Worklet 队列的首段释放，不放宽迟到完成回执校验。

## 验收边界

在 `FamilyTV_UI / emulator-5580` 上用真实 D-pad 事件验证三态、拨号、焦点、静音、结束及 Home；波形使用本地替身生成的实际 PCM 测试音。真实模型语音、真人听感、遥控麦/AEC、真实账号工具目录和实体电视仍未验收。未合入、未发布、没有系统语音键或唤醒词接管。最终三层源码与 APK 以 TV 仓库重做候选 manifest 为准。

共用 Voice 回归 972/972、speaker-native 95/95、iOS H5 生成产物一致性通过；TV 壳单测、lint、release 构建与桌面 205 项 JVM 测试、lint、release 构建通过。模拟器 13 项遥控路径通过，并另外从真实 IME 输入到报告卡片、全文阅读、返回和小态重开验证报告链路。报告打开时隐藏岛的收起按钮，避免与阅读器标题、返回重叠。

## 侧栏尝试（2026-10-26，已由后续分辨率修正取代）

用户否决 0.2 候选的报告密度：手机阅读器的标题、留白与底部控件放大后，一屏只有几行正文。TV 横屏报告改为正文主列 + 76 CSS px 侧边通话控件；顶部 44 px，正文 16 px / 1.6 行高，标题 23/19/17 px，缩小段距。只在 TV 且宽度至少 700 CSS px 的报告阅读器生效，手机与图片/视频阅读器保留原布局。相同三节方案在 1920×1080 模拟器中可完整显示。

阅读区域上下按可视高度的 80% 滚动，右键经过保存进入通话侧栏；侧栏上下移动至输入、静音和挂断，左键回到阅读区。保留原通话 owner 和报告全文。

## 当前方向：使用原 Web 布局与完整桌面画布

用户进一步指出：70–80 多寸电视有足够空间，根因是网页有效分辨率过低、整体放大，不是需要另做侧栏。撤回侧栏与 TV 专属的大字号/对话网格覆盖，恢复共用 Web 的居中文章和底部水平通话控件。

Android WebView 开启宽视口支持；窗口尺寸确认时传入窗口的实际 dp 宽度。共用 H5 在完整页采用至少 1600 CSS px 的视口宽度，并按窗口宽度计算页面缩放；中、小态恢复 1 倍比例。1920×1080 模拟器完整窗口实测从 912 CSS px 宽提升到 1600×835 CSS px；保留一个 WebView 和同一通话，切换窗口不重载。普通手机/Web 不执行 TV 壳缩放。

文字、段距、按钮与头像统一按原桌面布局缩放，原 Web 文章最大 940 CSS px 居中。方向键在阅读区翻动正文，经顶部保存进入底部控件，左右到静音/挂断，上键回到阅读区；文本框右键直接到发送，不误选挂断。

## 文件主体焦点与行宽（2026-10-26）

按用户反馈，TV 报告面板最大宽度从 940 收到 760 CSS px，保持居中、原字号和底部按钮。TV 文件打开后聚焦可滚动正文区域；完整页尺寸回执也恢复正文焦点，避免重新跳到顶部收起按钮。上下键在正文滚动约 80% 可视高度并保留焦点，左键到收起按钮，右键到原底部控制；通话控件上键回正文，遥控返回关闭阅读器。非 TV 页面保持原来的打开焦点与宽度。

本地长文 fixture 覆盖超过一屏的正文；通过真实遥控按键和打开、下翻、上翻截图验证滚动，检查长文后续章节实际进入画面，保留同一通话 owner。
