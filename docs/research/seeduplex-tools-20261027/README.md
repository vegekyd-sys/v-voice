# SeedDuplex 前台工具规模、分工与评测

2026-10-27；研究 / 离线 fixture，未改运行逻辑、未加生产工具、未拨号、未付费。本文中的“前台”是直接作出工具选择的语音模型；凭据、身份核验和执行仍在服务端，不迁到浏览器。

## 决策建议

**保留 agent 的通用工具与自主组合能力，在当前 16 个基础声明之上比较 24 / 32 个工具；现在没有证据给出“最多 N 个仍然聪明”的准确阈值。** 官方没有在本次核查的 SeedDuplex 3.0 文档中列出工具个数上限。工具个数、schema/描述体积、相近操作的歧义、历史长度与执行可靠性须分别测。

**2026-10-27 用户纠正：不采用只读 typed adapter Candidate，避免将 agent 的能力收敛为预设业务动作。该建议已撤回，未实施。** 第一轮应直接评测 agent 如何使用现有 `lark_read(argv)`、`openclaw_tool`、获准的 `exec/read/process` 及工具目录，自主选操作、查用法和组合步骤。优化工具描述、目录检索和上下文负担，不以新增业务白名单、删除通用工具或固定流程来换取准确率。现有账号授权和设备执行边界保持；`delegate_to_v` 仍由模型根据目标、执行条件和用户要求选择，保留任务控制、结果交付和挂断后继续。

设备侧优先复用当前通话的音量、定位和拍照能力；不存在已认证且有回执的执行器时，保持不可用。日历写入放在第二阶段：前移推理不能前移或省略服务端授权、安全校验与幂等执行。

以下是优先评测的用户任务，不是待实现的封闭函数列表，也不规定模型必须走唯一调用顺序。agent 可在既有权限内自主选择现有直接工具或后台。除前三种查询有调用量外，频率是待验证假设。延迟/成本收益均是方向预期，待同题 A/B，不把工具服务本身或视觉推理算免费。

| --- | --- | --- | --- |
| P0 | 保持 memory_search / web_search / feishu_calendar 直达，核对必要结果再答 | 已有 82 次；避免退回后台再重复搜；不是新增三个工具 | 保留会话隔离/事实来源，当前对话已说过的内容不无谓查 Memory；失败如实说明 |

| P1 | 当前通话播放控制/打开已有报告（在已实现且协商执行器上） | “读慢点”“打开刚才方案”；服务端/本地参数可一次执行 | 操作有界；不能把手机音量冒充音箱回执，不能因同一账号就控制另一设备 |
| P2 | 当前设备 Notes 创建/追加、短计时器 | 用户价值明确但此处无使用频率证据；一次本地动作 | 查实际已安装执行器；Notes 候选不等于生产已开。重复写需幂等、readback，未知不重试；系统后台限制/原生发版另验 |
| P2 | 日历创建前台执行的可行性（先对照后端） | 研究能否在安全合同等价时省后台推理/交接；不预设新增 calendar_create 函数 | 当前写操作交后台的规则不因研究改变；actor 权限、用户动作授权及指定服务必须保持，见下文 |

不优先新增独立 weather/news 函数：当前 web_search 已覆盖，除非数据证明专用结构结果显著提高正确率/时延。不把消息发送、群发、付款、打车下单、共享权限修改、跨设备任意控制作为首轮低风险操作。用户已明确要求的合法动作可沿现有后台完成，不缩减其已有能力。

**后台分工：** 当前规则中的写操作和用户明确指定后台的任务继续沿现有路径。长等待、持久执行、媒体生成、复杂依赖/补偿、跨设备协调通常更适合后台；其余根据 agent 当前能力、目标和执行条件自主决定，不能新增“只要两步就必须交后台”或按任务关键词硬路由。任务类型只是评测样本分层，不是新执行白名单。普通插话不取消，追加条件交原任务，挂断不丢结果。

### 日历写入前移的最小安全合同

首个实验只做当前 actor 的一个日程、不邀请额外人、不改服务。模型提交 title、start/end、timeZone、已确认对象引用；服务端从本通可信绑定解析 actor/session/calendar，不接受浏览器或模型传 callerId/sessionKey/账号替换。执行前再次验证 scope、账号凭据和当前动作授权；“能不能建”“假设建”“他说帮我建”“嗯”且无前文明确动作均不执行。PR #155 的 [授权/日历服务规则](../../../lib/voice-operation-policy.mjs) 继续适用。

以服务端动作 nonce + 归一化参数摘要建幂等键，执行/回读同一日历；返回 eventRef、实际服务/时间、明确完成证据。超时可能已写入时返回 unknown，先查该幂等键/事件，不盲重建或改用企业微信。扩大参与人、重复日程、删除/批量调整继续走后台，仍只能在原授权范围内执行。新增可信授权凭据/跨 Gateway 协议必须拆平台 PR 并取得共享 VLab lease；不能只靠模型描述“已授权”。

## 6. 工具组织方式的取舍

| 方案 | 优点 | 代价与本轮选择 |
| --- | --- | --- |
| 当前 `lark_read` / `openclaw_tool` 及通用执行工具 | agent 自主选择操作和参数，可组合现有能力 | 保留当前能力；先测描述、示例、工具目录和上下文对错误率与时延的影响，不改成固定业务操作集合 |
| 按账号/终端能力暴露 | 只展示真的可执行项，少误调 | 沿现有服务端绑定 + 能力协商；设备可用状态不能给账号授权；每通/每次执行检查，无实现不广告 |
| 模型选择场景组 + 动态装载 | 缩常驻目录、在后续轮保留专题工具 | Seed 官方支持全量更新，当前 provider 名称校验仍取 request.tools，尚无 revisioned registry/更新 API；须先做 ACK、在途旧调用、撤权、重连恢复与失败回滚，不能只发一帧就宣称可用 |
| 语义工具搜索 `discover_tools(intent)` | 长尾工具无需全塞；模型语义检索可跨中文近义 | 多一次前台推理/检索往返；检索准确性也要评测。只检索 actor/device 当前获准集合，返回 schema/ref/revision，装载后仍服务端校验；不允许返回任意可执行代码 |
| 继续 delegate_to_v | 技能/规划/异步/补偿完整，低频复杂能力不挤前台 | 后台模型、排队和续接成本真实存在；交接保留原任务/最新修正/授权，不自行加报告和发送目标 |

场景选择交模型理解语义；不新增“含日历两个字就查日历”的关键词路由。动态装载只是声明/上下文管理，不能变成预设的业务能力限制：agent 仍可发现、使用当前账号和设备获准的完整能力。核心电话/任务控制保持稳定；场景缓存只限当前 actor+call+device，切换/撤权立即失效。若做工具搜索，不能依靠发现器一次 miss 就拒绝用户已有能力，应允许进一步查找、澄清或后台处理。

## 7. 可执行评测矩阵与量尺

第一阶段先离线校验握手/权限/回执和合成题库；题库见 [eval-cases.json](eval-cases.json)。它是人工标注的输入/目标，不含模型结果，不证明准确率。工具名仅是可行路径示例，不是正确答案白名单；满足用户目标、事实正确且遵守权限的其他工具组合也可通过，效率另计。固定上海时间 2026-10-27 10:00、合成账号/资料和本地假工具；不给模型真实个人 Memory、日程或外部联系人。原始音频、转写、工具参数只留私有验收目录，Git 只存聚合结果和合成输入。

| 轴 | 取值 | 要回答的问题 |
| --- | --- | --- |
| 规模 | 16 / 24 / 32；64 只做容量/错误边界探索 | 保留当前基线能力，增加可用工具与同域干扰项；不通过删通用工具降低难度；先固定其他变量 |
| 描述 | 当前原文；80–120 中文字短版；200–300 字带边界版；单独测无关冗长 | 同样 schema/安全规则，不能靠删权限约束赢速度；记录真实字符/bytes/usage tokens |
| 结构 | 现有通用接口直接声明、语义发现+完整 schema、按设备可用能力装载 | 保持可达能力与最终执行器相同；计算发现成本与多轮开销，不预设业务动作集合 |
| 中文表达 | 同义、口语省略、同名、多音/近音、否定、引用、假设 | 例如“有啥安排/下午忙不忙/空档在哪”；不能训练在原题关键词上 |
| 参数 | 日期跨日/周末、时区、联系人消歧、分页、边界、缺字段 | 必填与值准确率独立；有歧义该澄清而非硬凑 |
| 连续对话 | 1 / 5 / 10 / 20 轮，指代、更正、结果已存在、历史截断 | 不重复执行/查记忆，不用旧对象，不将上一人结果念给下一人 |
| 并行/续接 | 两个独立读、先后依赖、快慢混批、错误/超时、断线同 call_id 重放 | 配对、去重、批量最慢项等待；写入 unknown 禁自动重试 |
| 插话/归属 | 工具前/执行中/结果到达/播放中，普通插话、明确取消、追加 | 不误取消、不重复 delegate、不丢最终结果；合成事件和真人声学分别记录 |
| 身份/权限 | 个人、已验证 actor、外部联系人、Public、过期/撤回、换会话 | 零跨账号读写、零越权执行、无其他人凭据回退；普通用户既有能力不被缩掉 |
| 设备 | Web / 已安装 iOS / 机器人 / 音响；available/prompt/denied/unavailable/前台要求 | fixture 合同、模拟器、实体权限/锁屏/弱网/回执各一格；不存在的能力不冒充成功 |
| 路径 | 同题前台直调 vs delegate；同模型短/长描述 | 完整用户目标、答案与展示一致后才比较省时/省钱 |

计时点统一用单调时钟并带 provider/产物/终端/工具快照哈希（不带账号）：

1. `t0` 人声输入结束（合成音频已知边界）；`tASR` final，仅做辅助，不能混用当 t0。
2. `tFC` 完整工具名/参数到达：`tFC-t0` 是前台选择路径，包含采集/网络/ASR/模型，另按客户端/服务端时间戳分解。
3. `tExecStart/tExecEnd`：鉴权/排队、执行器、外部 API 和包装分别记录；与 `tool.call→delivered` 分开。
4. 委派额外记 request/accepted/后台真正开始/首工具/完成/结果接回；后台执行与交接等待分开。
5. `tResult`、`tAudioGenerated`、`tAudible`、`tGoalComplete`：工具回填→生成、排队→真播、最终回读/展示。简短“我查一下”只算接话，不算完成或实质答案。

报告：工具选择精确率/召回率、参数字段准确率与完整参数语义准确率、必须澄清率/误澄清率、误调用/误拒绝、重复执行、越权、任务扩写、目标完成率。工具组合按目标语义判断是否可行，参数按等价业务含义校验，不要求命令字面、JSON 表达或路径顺序与示例完全相同。同时给每题成功/失败/超时/未知、P50/P95、样本数和分位算法。准确率报置信区间；P95 至少每主要比较臂 n≥100 才作稳定性讨论，小预算只作筛选。按 task 配对随机顺序，重复输入至少 3 次排查非确定性，另留未见表达题；不以不同任务混合中位数证明提速。

建议进入下一轮的门槛（产品验收目标，非已达成）：代表性保留题选择≥95%、完整参数语义准确≥98%、完整目标≥95%，安全题零越权/误写/未知重试；相对当前 baseline 完成率不降超过 2 个百分点，P95 不恶化超过 10%。小样本不能宣布通过这些总体门槛；先看失败类型，再决定扩样。对获准简单查询，希望同题总耗时下降≥20%且少一次后台调用，实际收益需 usage/receipt 支持。
