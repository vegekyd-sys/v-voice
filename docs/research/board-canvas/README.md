# 讲解画面：自由画布 + 指针（研究）

方向（Tianyi 2026-11-18）：给 V 更少的组件，但组合上限要足够高。例如讲喷气式发动机，真的能画出发动机，再一个个讲重要部件，接近 HeyClicky（光标旁的老师，讲到哪指到哪）。

## 第一轮（2026-11-18）

- 画布格式：400×300，部件 = 名字 + 一句说明 + 指针停留点 + 2–3 个图形（path 只用 M/L/C/Q/Z、circle、ellipse、rect，固定调色板），另有「流动」路径（气流、血流）。提示词在 `scripts/candidate/canvas-eval.mjs`，渲染在 `scripts/candidate/canvas-render.mjs`。
- 10 个自拟题（发动机、心脏、火山、相机、马桶、自行车变速、日食、光合作用、冰箱、拱桥），DeepSeek Flash 不思考（2–3.5 s）对比开思考（37–74 s）。结果 `round1.jpg` / `round1.json`。
- 不思考：约 7/10 能讲（心脏、火山、日食、拱桥较好），结构复杂的（自行车）差；标签互相压叠是渲染问题。开思考：更像（发动机有主轴叶片、自行车完整），但 40–70 s 且 4/10 输出被思考吃光。
- Tianyi 的意见：这些题不是实际常用场景，不思考画得都一般。下一步要从最近的真实通话出发，找出实际被问的东西，给出最好的图解方式。

## 第二轮：从真实通话出发（2026-11-20）

### 1. 实际在问什么

统计了约一个月的生产和 candidate 通话（按「天 × 人」计，测试题已排除；原始记录只在本机分析，不进仓库）。问题按类别概括：

| 类别 | 例子（已概括） | 当时的页面 |
|---|---|---|
| 宝可梦 | 属性相克、进化链、某只长什么样 | 节点连线、带图列表、图集 |
| 自家系统 | 夜班进展、V 和团队怎么协作 | 时间线 + 步骤 + 列表 |
| 体育 | 今天的比赛、球员伤情、按位置排阵容 | 列表、数字卡；阵容也只是列表 |
| 旅行/地点 | 景点怎么逛、城市怎么玩 | 照片 + 时间线 + 列表 |
| 游戏 | 新游戏评价、找截图 | 图集、列表 |
| 产品对比 | 电车和油车、模型哪家好 | 照片 + 对比表 + 便签 |
| 知识讲解 | 几何定理、方程、生物原理 | 自画示意图、公式 |
| 健康/家庭 | 日常健康问题 | 列表、便签 |
| 天气/日程 | 气温、安排 | 基本不需要画面 |

生产上画过的 366 页里，列表占 47%、便签 41%、照片只占 15%、自画示意图 10%。真实问题里，「长什么样」「哪个部位」「站在哪」这一类很多，但今天的画面几乎都用文字去回答它们。

### 2. 照片 + 指针能不能实时做

11 张 candidate 已缓存的真实搜索图（宝可梦、太和殿、屋脊兽、两款车、埃菲尔铁塔、斗兽场、游戏截图），讲稿按标点切成编号小段，让 DeepSeek Flash 对每段给出要圈的位置（0–1000 坐标）。脚本 `scripts/candidate/pointer-eval.mjs`，在 V 上以 nobody 身份、只用 candidate 的 key 运行（`pointer-eval-on-v.sh`）。

| 方式 | 耗时 | 结果 |
|---|---|---|
| 看图、不思考 | 0.9–2.1 s（中位约 1.5 s） | 大而明显的部位约七成圈对（屋顶、匾、台基、角、舌头、格栅）；小的或易混的会错（尾巴圈到头上、车顶圈到车上方、游戏里两个角色圈反） |
| 先说位置再给框 | 1.3–3.0 s | 单独的效果没有逐项量化；原型采用「先说位置 + 放大校正」 |
| 先说位置 + 放大校正（按粗框裁图再问一次） | 2.4–4.2 s | 小幅改善；一开始就框错的（如车顶）救不回来 |
| 开思考 | 9–43 s | 更准，但实时用不上 |
| 不看图 | 0.9–1.6 s | 构图固定的照片能蒙对，具体部位基本错 |

结论：要指得准，模型必须看到图；不思考的准确度够用，前提是**只圈大部位，看不到的东西不指**（加油口、充电口这种照片里没有的，模型会猜）。

### 3. 原型：讲到哪指到哪

七个真实题（超梦长什么样、泡沫蛙进化、属性相克、太和殿看点、电车和油车、巴黎阵容、夜班流程），讲稿参照真实通话写，阵容那页直接用当时 V 的回答。底图收成几种：一张照片、几张照片一排、三张摆成三角、球场、白纸。模型一次生成整页的步骤，每步挂在讲稿的某一小段上（和线上 cue 同一套切法），页面按朗读逐句执行：指针飞过去、画圈、贴名字、连箭头。

- 生成脚本 `scripts/candidate/canvas-proto.mjs`（`canvas-proto-on-v.sh` 在 V 上跑），页面模板 `canvas-proto-page.html`，打包 `canvas-proto-page.mjs`（照片只在打包时嵌入，不进仓库）。
- 只用画布：1.7–4.1 s，首字约 1 s，都能和 V 开头一两句重叠准备。

### 4. 和线上比，再结合

用线上的 cue 画面模型（`CUE_INSTRUCTIONS`）跑同样七段讲稿，用线上真实的 `Board` 组件渲染（`canvas-today.mjs`、`canvas-today-page.mjs`），逐题并排比较：

| 题目 | 线上现在 | 只用画布 | 结论 |
|---|---|---|---|
| 夜班流程 | 时间线 + 步骤，干净好读 | 名字散在白纸上 | 线上好，纯文字 |
| 电车和油车 | 对比表清楚，车只是小图 | 能圈车头，但补能、花费指不出来 | 结合 |
| 太和殿 | 看点清单好读，照片小 | 照片大，能圈屋顶、匾、台基 | 结合 |
| 超梦 | 一张小图 + 文字 | 直接在身上圈部位 | 画布好 |
| 泡沫蛙进化 | 三张小图，第一张拿错了图 | 三只大图 + 箭头写等级 | 画布 + 步骤 |
| 属性相克 | 节点和箭头挤在一起 | 三角 + 绕圈箭头 | 画布好 |
| 巴黎阵容 | 阵型是一团看不清的小圈 | 球场上逐个放人 | 画布好得多 |

结合版（`MIX=1`，模板 `canvas-mix-page.html`）的分工规则写在提示词里：

- **看得见的**（长相、部位、建筑构件、车的外观、站位）放在照片或球场上，用指针圈；
- **看不见的**（步骤、时间、规则、数字、对比、结论）写成线上那种文字条目：步骤、时间线、列表、对比、便签；
- 同一样东西只出现在一处；一页最多两个文字块，每块 2–5 条；没有底图就只出文字；
- 同一个指针在照片和文字条目之间走，讲到哪一条，那一条就被荧光笔标出。

结合版一次生成整页 2.0–4.5 s（线上 cue 画面 1.4–2.1 s）。

Tianyi 看过后的两条修改，已做进模板：

- **圈讲过就消失**：讲到下一句，上一个圈和它的标注淡出，画面上只留正在讲的那一个；讲完后最后一个也淡出，只剩照片和文字。照片下的名字和表示关系的箭头保留。
- **照片像便签纸**：照片加浅黄纸边、胶带和阴影，和文字区的便签同一个样式。照片不倾斜，以免圈和部位错开。

### 5. 结论

- 方向：**一个模型同时出画布和文字**（Tianyi 2026-11-20 确定）。分工要靠同一个模型判断，拆成「线上画面 + 另一个看图指针模型」容易两边重复。
- 模型：DeepSeek Flash 看图、不思考。整页 2–4.5 s，可以和 V 开头一两句话同时准备；思考只适合能提前准备的场景。
- 组件保持很少：底图（照片 / 几张照片 / 三角 / 球场 / 无）+ 指针动作（停住、圈、箭头、名字）+ 线上已有的五种文字块。
- 天气、日程这类不需要讲解画面。

### 6. 还没解决的

- 照片圈错约三成，主要是小部位；规则上只圈大部位、看不到的不指，还需要在更多真实题上验证。
- 模型偶尔把同一件事既圈在照片上又写进清单（太和殿的屋顶）；对比表偶尔出现「—」空格。
- 球场那页给每个球员都画圈，显得乱；放人的页面应该少圈或不圈。
- 手机上 4:3 画布偏小，上产品前要给手机做竖版布局。
- 指针动作要和真实的流式讲稿对齐（这里是整段讲稿一次生成），首字和逐句跟随还没在真实通话里测过。
- 照片来源沿用线上的找图（`createPhotoFinder`），图找错（线上泡沫蛙那页拿到了标志图）会直接影响圈的准确度。
