# 跟随由模型写出来：研究方案

状态：研究中（草稿 PR），未改线上行为。2026-11-14。

## 问题

Tianyi 对 #220 的反馈：讲解区先显示回复文字、整页先灰字出现，都像是为了尽快有画面而凑出来的，不优雅；灰字还像剧透。
他提出：「什么时候出现、跟到哪」也应该和讲稿、图示一样，是模型生成的一部分，不应该写死在代码里。

## 现在「跟随」是怎么决定的

画面由模型画；但每样东西**什么时候出现**、**高亮跟到哪**，基本由代码里的文字匹配决定。

| 位置 | 写死的规则 |
|---|---|
| `board-lesson.mjs` `settleLesson` | 无视模型给的 `q`，改挂到「名字第一次被念出来」的地方；图示类信 `q`、角色类信名字；严格模式下删掉没念到的条目；flow 的箭头挂到「两端第一次同句出现」的句子；照片挂第一句，便签挂最后一句非问句；`quoteAt` 取 4 个汉字或 10 个拉丁字母作为唯一开头 |
| `board-lesson.mjs` `refineStreamOp` | 边说边画时，把条目重新挂到「V 更早用过这几个字」的句子 |
| `board-scene.mjs` `anchorOf` | `q` 找不到时，退回去找标题的前缀（最少 3 字）、数值加单位 |
| `board-scene.mjs` `spokenProgress` | 用 `quoteHead`（前 4 字）在已念文本里找位置；回头再说一遍全文时焦点回去 |
| `board-client.mjs` `createLessonGate` | 讲稿开始被念之前全部隐藏；判断「开始念了」靠 `speaksOf` 文字匹配；15 秒没开始就全显示 |
| #220 | 空页显示回复文字；未念到的灰色显示 |

这些规则各自修过一个真实问题，但叠在一起有三个后果：
- 模型其实知道「这句话讲的是哪个东西」，却被文字匹配推翻了，猜错时画面就对不上。
- 为了不剧透就整页藏起来，为了不空就整页灰显，两头都是补丁。
- 每遇到一个新反例就再加一条规则。

## 提议：模型给每样东西写「挂在第几段」

核心改动：**跟随不再靠找字，靠编号。**

1. **把文字切成编号小段。** 讲稿（或 V 自由回答的文字）按标点切成小段，前面标上编号再交给画面模型：

   ```
   [0] 电车和油车最大的区别在补能。
   [1] 电车在家充一晚就满，
   [2] 油车去加油站三分钟加满。
   [3] 但冬天冷的时候，
   [4] Model 3 的续航会缩水一截。
   ```

   切段只看标点，是测量，不涉及判断「讲的是什么」。

2. **画面模型给每个操作写 `at`。** 每个 put、每个条目、每条箭头、每次高亮（focus）、每个荧光笔标记，都带上自己挂在第几段：

   ```
   {"op":"put","at":-1,"block":{"t":"photo","id":"p","q":"特斯拉 Model 3"}}
   {"op":"put","at":1,"block":{"t":"versus","id":"v","cols":[…],"items":[{"id":"r1","h":"补能","at":1}, …]}}
   {"op":"focus","at":4,"id":"v/r3"}
   {"op":"mark","at":4,"id":"v/r3","kind":"circle"}
   ```

   `at: -1` 是开场画面：用户刚问完、V 还在说「好，我讲讲」时就出现的东西（标题、要讲的那个东西的照片）。
   有没有开场画面、放什么，由模型决定，代码不再用灰字或回复文字去填空。

3. **页面只播放时间线。** 声音进度换算成「念到第几段」（现有的音频进度测量保留），页面就显示 `at ≤ 当前段` 的东西，高亮按 focus 操作走。
   没念到的东西就是不出现，所以不会剧透。不再需要猜「开始念了没有」。

4. **讲稿作者也用编号。** 讲稿模型的 `show[i]` 已经是「第 i 句的画面提示」；它可以细到小段，画面模型照着写 `at`。
   画画仍由同一个流式画面模型完成（保持「一个流式画面模型」的目标）。

## 可以删掉的代码

`settleLesson` 的重挂、`refineStreamOp` 的重挂、`anchorOf` 的退路、`quoteHead` 唯一性、`createLessonGate` 的 `speaksOf` 和 15 秒耐心，以及 #220 的灰字与空页文字。

保留：音频进度测量、按标点切段、页面渲染。

## 要验证的问题

| 问题 | 怎么量 | 合格线（初定） |
|---|---|---|
| 模型挂的段对不对 | 每个条目所在段是否真的讲到它：DeepSeek 判 + 我抽查 | 对应率不低于现在的文字匹配 |
| 剧透 | 东西出现在它被讲到之前的比例 | 低于 5% |
| 空屏 | 按念速模拟，从用户问完到页面上第一次有内容的秒数；V 开口后页面为空的秒数 | 比现在短；开口后空屏接近 0 |
| 速度 | 画面模型第一条操作的时间；讲稿开始念的时间 | 不变慢（输出多了 `at` 字段） |
| 效果 | 每页图示种类数、条目数（沿用 board-bench） | 不少于现在 |

数据：board-bench 的挑战题（ch1–ch10、lesson、follow、result 等组），跑现方案和新方案各一遍，同口径对比。
模型只用 DeepSeek。先离线跑（不打电话），合格后再上 candidate 打真实电话，最后才谈上线。

## 风险

- **模型挂错段。** 文字匹配至少保证「名字被念到」；模型可能挂早。对策：提示词要求挂在「第一次讲到它」的段，评测里量出来；不行再考虑只保留一条兜底规则：挂在名字出现之前的段时，往后挪到名字出现的段。这条要有数据支撑才加。
- **V 自由回答时文字在长。** 编号要稳定：已经切好的段编号不变，新文字只在后面追加新段。边说边画时，模型只能给已有的段写 `at`。
- **讲稿被打断。** 用户插话后讲稿不再念完，后面的段永远不到，后面的东西就不出现。这和现在的行为一致。

## 分步

1. 离线原型：画面模型输出 `at`，加一个页面时间线播放器，放在开关 `VOICE_BOARD_FOLLOW=model` 后面（默认关）。在挑战题上和现方案对比，结果写进本目录。
2. 指标合格后上 candidate，打真实电话（Public 手机尺寸 + iPhone App）。
3. Tianyi 认可后再谈上线；上线后删掉被替代的规则。

## 第一轮离线结果（2026-11-14 23:40 CST）

脚本：`scripts/candidate/follow-eval.mjs`（`follow-eval-on-v.sh` 在 V 上用 candidate 的 DeepSeek key 跑，不打电话、不碰服务）。
19 道题（lesson 组 + 挑战题），每题先用现在的讲稿作者写一份讲稿，再交给两个画面作者：
- **现方案**：今天线上的流式画面作者，写 `q`（抄原话），代码按找字重挂（`refineStreamOp`、`spokenProgress`）。
- **cue**：同一份提示词，只把「抄原话」换成「写挂在第几段」（`follow-cue.mjs`），代码不再找字。

由 DeepSeek 评审：每样东西第一次真正被讲到的是第几段。只有图形没有字的示意图元素（评审没法判断）单独计数，不算进比例。

| 指标 | 现方案 | cue |
|---|---|---|
| 挂对段（同一段） | 72% | 70% |
| 提前出现（剧透） | 8%（相差超过 1 段的 15 个） | 5%（6 个） |
| 提前多少秒（中位数） | 9.4 s | 2.3 s |
| 晚出现 | 42 个（相差超过 1 段的 13 个） | 71 个（31 个） |
| V 开口后画面为空（中位数） | 0.6 s | 0 s |
| 用了开场画面（cue -1）的页 | — | 0 / 19 |
| 每页图示种类 | 1.74 | 1.79 |
| 画面作者首条 / 整页（中位数） | 0.74 s / 2.95 s | 0.82 s / 3.50 s |

同一套现方案在第一轮的挂对率是 63%，第二轮是 72%：讲稿每次重写，题与题之间波动大约 ±10 个百分点，单轮差几个点不说明问题。

**看得出来的：**
1. 不找字，模型自己写段号，挂对的比例和现在差不多。也就是说，那一整套找字规则可以删掉而不变差。
2. 剧透少且短：现方案一旦 `q` 抄不准就整块不受控，例如 iPhone 历代那页 8 代机型全在第一句就出来（提前 2 到 17 段）；cue 的提前基本只差一段。
3. cue 的「晚」多，但很多是评审口径问题：结尾的总结表（「三样关键区别」）、结论处的打勾打星，本来就该在总结时出现，评审按「第一次提到」算成了晚。真正的问题是有的页把前面讲过的东西集中挂在了总结段（关西五天那页，前面几天讲的时候画面没动）。
4. 第一版提示词里，模型常只给整个区块写一个 cue，导致整条式子在第一句全部出现（奶茶成本那页）。要求「每一项都有自己的 cue」后，这类情况没有再出现。
5. 模型没有用开场画面：它不知道开场画面对用户意味着什么，只靠一句说明不够。

**还不能下结论的：** Tianyi 反馈的空屏（问完到出画面那几秒、讲稿开始念之前）发生在真实通话的时序里，离线评测量不到，要上 candidate 打电话量。

## 下一步

1. 评审口径：总结区块和结论笔迹单独判（「是不是该在总结时出现」），再抽 30 条人工复核评审。
2. 提示词：把「讲的时候就画，总结时只落笔」写清楚；开场画面给例子。
3. 原型：服务端按 cue 生成时间线，页面只按段号播放（开关 `VOICE_BOARD_FOLLOW=cue`，默认关），上 candidate 用 Public 手机尺寸打电话，量空屏秒数和对应感。
