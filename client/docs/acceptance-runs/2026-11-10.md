| 问题 | 怎么发现的 | 修法 |

## 第二轮（2026-11-10 晚至 11-11 凌晨 CST）：真机反馈后的重做

第一轮在模拟器和演示数据上「通过」，装到真机后 Tianyi 的评价是「体验还是挺糟糕的…就是不丝滑」。这一轮按真机反馈逐条重做，结论以真机复测为准，下面只记已经证实的。

### 改了什么

| 反馈 | 根因 | 处理 |
|---|---|---|
| 进页面一直滚 | SwiftUI ScrollView 做不到「打开即在底部」 | 聊天列表换成 UITableView，首次显示在 `viewIsAppearing` 里定位到末尾 |
| 键盘弹起后发送不好 | 输入框与列表各自跟键盘 | 输入框底边绑 `keyboardLayoutGuide`，贴底用 display link 弹簧 |
| 只看到两三条、点了不加载 | 历史一次取整段、内部消息过滤后所剩无几 | `HistoryWindow` + `HistoryPager`：首屏 30、更早页 60、可见项少于 12 自动续载，失败有重试行 |
| 普通，没有 V 的形象 | 紫色主题的通用聊天壳 | 首页薰衣草面板 + V 半身像；V 的回答不加框；工作时底部「在场行」随工具换立绘 |
| 不要绿色；气泡「太接近绿色」 | 主色取了外套的青蓝 | 主色改暮紫（`VTheme.dusk`），全库无绿、无青 |
| 命令不用出现、文字重复、要像两个人聊天 | 工具行和 commentary 都画了出来 | 不显示命令与运行统计；commentary 与正文二选一；计划清单保留（Tianyi 要求） |
| 发出去的图片看不到 | 历史映射只读正文里的 `[media attached]`，Gateway 实际放在 `__openclaw.media`；纯图消息被整条跳过 | 读 media facts，映射回本地副本 |
| 正文回复不更新（卡在「正在回答」12 分钟） | 手机挂起漏掉结束事件；`merge` 让本地进行中项无条件覆盖历史 | 历史读取时判定已结束的 run 并收敛；回前台与 45 秒静默看门狗对账；停止一定能清；连接探活 |
| 飞书群显示成「V · iPhone」私聊 | `chat.send` 会把会话行的 chatType/origin 改写 | 会话类型与渠道从 key 推导 |
| 往上翻时画面跳 | 手指按住时插入行被拖动偏移覆盖并连环加载；屏幕外变高的行沿用旧高度 | 页等手指抬起再插入；快照期间不再触发加载；恢复位置前重读高度 |

### 怎么验的

- 单元测试 86 个全过（`VClientTests`），UI 测试 16 个全过（`VClientUITests`）。位置类 UI 用例用截图量像素位移：向 app 询问 frame 会让表格实测所有行，列表自己会动。
- 模拟器 Release 构建录屏逐帧看过：打开长对话、键盘弹起、发送、思考到完成、回复折叠、上翻历史。
- 演示数据新增三个钩子，覆盖真机才有的形态：`VCLIENT_DEMO_VCARD=1`（回复是一张不断改写的卡片）、`VCLIENT_DEMO_HOLD=<阶段>`（停在某阶段）、`VCLIENT_DEMO_DROP_FINAL=1`（吞掉结束事件，随后历史返回已结束的转录）。
- 回复卡住的根因用生产 V 上这次会话的只读记录对照过（服务器 2 分 10 秒就结束了），记录未入库。
