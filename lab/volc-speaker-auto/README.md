# 自动多人对话 Candidate

当前入口（2026-10-16）：<http://127.0.0.1:26319/>。只显示一个“自动多人对话”，不再让用户选择“多人自适应/共同对话”。本候选独立于生产 Voice V、GPT Live、Grok 原生入口和 Gateway。

默认 `auto` 下，所有辨认出的 Speaker 话语与身份、历史、当前重心一起交给同一文本模型。模型自主选择是否回应、回应一人或多人、调整对话重心。程序不再按问句关键词静默旁人评论，不强制把回复扩展到全体，也不把最后开口者直接当成主要对象。保持安静时不启动 TTS、不取消旧语音；决定回应后才切换播放。这也意味着本候选自动模式的语义打断需等模型判定，并非即时声学打断。

“只跟十二聊”等明确指令是会话中的专注约束：保留原有依据校验和模型前过滤；“解除专注，大家自由聊”回到 auto。历史 adaptive/group 协议仍供旧测试复现，页面不提供这些入口，auto/exclusive 链路也不会进入它们。

实际链路仍为：火山 Seed ASR 2.0 分人 → Doubao Seed 2.1 Lite 文字决策 → 原 Seed TTS 2.0 / 小何 → 原 MP3 流式播放器。此次不改模型、音色、TTS 参数和播放协议；模型用于对象判断的控制字段不念出声。人物资料更新如果缺字段或缺可核实原话，会保留原资料/未知状态，不再让可选资料错误中断正常回复；这些被隔离的资料也不能用来完成专注交接。

重要边界：这是输入信息增强和多人决策的候选验证，并非三家原生语音模型的完整接入。对原生入口，需要把人物信息对齐到音频轮次，并处理模型自动开口与标注先后到达的问题，不能简单在音频旁追加一条无关联的姓名提示。

| 原生入口 | 目前确认的接入点 | 本轮状态 |
|---|---|---|
| GPT Live / gpt-live-1-codex | 现有 H5 用 `session.context.append`；当前官方 Live 文档的 `session.thinking.append` 等事件与当前代码存在版本差异 | 只读核对；未调用或修改原生模型，需按实际服务版本验证 |
| 豆包·小何 / Seeduplex | 当前端点是 `/api/v3/duplex/realtime/dialogue`。官方 Seeduplex 3.0 JSON 协议与本地适配器支持上下文注入；本地 `sendUserMessage` 只追加历史，不能当成一次响应触发。另一套端到端协议的 ChatTextQuery 不可直接套到此端点 | 当前通过的是分人＋文字模型＋小何 TTS；原生链路未验证 |
| Grok Voice 3.0 | 官方支持 user `input_text` 和 `response.create`，现有适配器已有该路径 | 接口可适配；Speaker 对齐、静默及不中断行为未做真实调用验收 |

官方依据：[OpenAI Live](https://developers.openai.com/api/reference/resources/live/primary-websocket)、[火山 Seeduplex 接入协议](https://docs.volcengine.com/docs/DoubaoVoice/access-mustread?lang=zh)、[Grok Speech to Speech](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech)。不能拿 OpenAI Realtime 的 `conversation.item.create` 直接替代当前项目使用的 GPT Live 协议。

新候选保留以下限制：匿名声线只在本次会话有效；姓名是对话告知或模型推测，不是认证；短句可能被 ASR 合并；重叠语音波形分离未通过。电视/旁聊测试只能证明模型能对相应转写选择安静，不代表真正声学电视声检测或噪音分离。真人原始音频不保存，验证素材是合成音色。

单会话 3 分钟，进程上限 60 次对话调用、10 分钟输入、6000 字 TTS。沿用单轮约 5 美元、合计不超 10 美元的 API 试验预算，以供应商实际账单为准。凭据仅从 `VOLC_SPEAKER_ENV_FILE` 读取，推理接入点文件在忽略的 `artifacts/volc-speaker/ark-endpoint.json`。

当前 35 项本地测试和旧实验 7 项回归通过；旧 adaptive/group 相关测试保留作历史回归。真实供应商音频链路的 57.58 秒合成输入验证通过：8 次发言、3 个 Speaker、自然姓名关联和明确专注交接、2 次非目标过滤、实际 TTS 返回；拼接 MP3 完整解码通过。此结果不代表真人声线验收。

自主策略的文字模型试验存在不稳定结果。曾观察到单人/多人回应、普通评论接话、人对人交流和电视式转写静默；“我们去拿水，等会再聊”则被礼貌回应，不能保证旁聊必然静默。最新严格验证 `auto-model-verification.json` 的 `passed=false`：第 4 次调用给出父亲和孩子各自建议，却只把孩子列为回答对象，因而双人对象断言失败，后续场景未执行。失败回执保留；不通过程序强制扩展为全体来掩盖这一语义/标注偏差，也不以此前偶然通过替代稳定性证据。

2026-10-16 内置浏览器回放“自然插话”：自动识别 A/B 两位 Speaker，A 自我介绍关联姓名；B 的普通补充由模型回应，重心仍保留 A。两条回复没有策略错误卡片；最新音频播放到 6.816 秒结束，readyState=4、error=null。页面估算本轮停口到首音分别为 3906/2392 ms，属于两次观测，不是延迟基准。684 px 侧栏页面无横向溢出、无框架遮罩，应用控制台无错误；截图 `/tmp/v-voice-auto-dialogue.png`。测试未访问麦克风，完成后释放会话。原生三模型的 Speaker 对齐、语义静默和抢话均未通过此次 Candidate 证明，不能据此直接上线。

# 无注册、无校准的自动 Speaker Candidate

独立候选入口：<http://127.0.0.1:26319/>。代码位于 `codex/volc-speaker-modes` worktree；旧的 `lab/volc-speaker` / 26318 保留，不接入生产 Voice V、Gateway 或音箱。人物关联仅用于对话，不授予工具或账号权限。

## 行为

Seed ASR 2.0 的流式说话人标注 → 匿名会话声线 `speaker:0` / `speaker:1` → Doubao Seed 2.1 Lite 根据带 Speaker 的话语关联姓名、选择回应对象 → 小何 TTS。

- 无声纹注册请求、无预设姓名映射、无“下一句是谁”校准。真人与合成回放使用同一条应用链路，`synthetic` 不参与身份判断。
- 初次开口显示 Speaker A/B/C，姓名和角色保持未知，可以直接匿名聊天。首个 Speaker 是初始主要对象。
- 模型通过自我介绍、明确的人物介绍或上下文更新资料，并引用话语 ID 和原文。界面区分“对话告知”和“模型推测 / 可能是”；两者都不是声纹认证。猜测不能覆盖已告知姓名，明确纠正可以更新。十二这个名字不等于年龄。
- `adaptive`：所有 Speaker 的话语和会话状态交给模型，但围绕主要对象；旁人普通评论不接话、不打断，明确向 V 提问/自我介绍可以单次回应，不因此接管主要对象。`group`：对共同话题的评论可接话，回复面向已加入的所有 Speaker。程序会分别约束回应对象、主要对象保持和插话打断，而不只依赖提示词。当前对“明确提问/自我介绍”的辅助规则以中文用语为主，并非完整语义分类器。`exclusive`：按已识别的声线 ID 在对话模型前过滤，改名不改变放行声线，首次进入该模式默认锁定首个开口者。
- “你先介绍自己”只建立对话背景，不能自动进入专注模式。模式变更和专注交接须引用明确指令；程序核验引用及明确切换用语，拒绝只有模型布尔标记的升级。专注切换清空原话历史，人物资料的引用也不再传给该模型，保留姓名、角色等状态。
- 对方尚未开口时可以在多人模式记录待交接人，等自然开口并关联后完成交接。严格专注状态不让陌生声线的内容进入模型，因此无法在该状态中直接识别一个从未听到的人；需要先恢复多人模式让对方开口。这不是注册或校准。
- ASR 修订说话人编号时清除相关语义身份和历史；若涉及当前目标则暂停会话，要求重新开始，避免旧姓名继续控制放行对象。

## 试用

1. 打开候选地址，可点“回放自动识人测试”，不启用麦克风。
2. 点“开始真人测试”即可自然聊天，可以先不说名字，也可以说“我是天意，是十二的爸爸”。
3. 另一位自然加入。没有明确自我介绍时，观察是否显示“可能是十二”；说“我叫十二”后观察关联依据。
4. 在多人模式说“现在只和十二聊天”，观察主要对象变为对应 Speaker、表达适合孩子、其余声线转为“未调用对话模型”。如果对方还没开口，可以说“等十二开口后只和十二聊天”。
5. 结束后释放麦克风；新会话重新匿名识别，不跨会话记忆声线。新会话清空页面原对话，防止不同通话的 Speaker 标签混淆。

## 验证与限制

2026-10-15 初版：19 项本地逻辑测试及旧实验 7 项回归通过。真实 API 的 57.58 秒合成输入包含 8 次发言，返回声线序列 `0/1/0/1/0/0/2/1`，没有姓名预绑定。

真实应用协议验证：姓名来自音频转写，第二条声线先被推测为十二，自我介绍后改为对话告知；普通介绍保持多人模式，父亲明确要求后才转为只跟十二聊，原父亲声线和第三条声线被模型前过滤；最后的孩子提问获得实际 TTS。6 次对话调用、12,655 tokens，单次模型耗时约 2.5–4.9 秒，另有 ASR 确认及 TTS 延迟。回执 `artifacts/volc-speaker/auto/verification.json`；MP3 完整解码通过，24 kHz 单声道。

额外 6 次真实模型调用（文字输入，用于策略验证，不冒充音频验收）：无人物信息时两条声线都保持未知；不把尚未开口的十二关联到父亲；等十二自我介绍后落实待交接的专注请求；同声线可明确纠正姓名。回执 `model-edges.json`。

浏览器复测曾发现模型把普通介绍误判成专注请求，已增加引用核验、明确切换用语检查和相应回归。姓名、角色及切换意图的语义判断仍有模型误判可能，当前校验用语以中文试用场景为主。

最终内置浏览器复测（684 px 宽，实际右侧面板）：从初始匿名状态点击回放，出现 3 个 Speaker；“可能是十二”经自我介绍变为“对话告知”；普通介绍不切模式，明确交接后才专注到 Speaker B。页面展示 6 条模型回复、2 条过滤，错误卡片为 0；播放器拿到 9.48 秒音频并加载完成（readyState=4）。页面 URL/标题、非空、无框架错误遮罩、应用控制台、截图及交互检查通过，无水平溢出。未验证独立桌面宽屏或真实手机。自动化工具自身偶有 Statsig 遥测请求失败，不属于本应用。回放结束后已释放会话，页面恢复为可开始真人测试的默认状态。

以上为合成音色和真实供应商 API 验证，不代表天意与十二的真实声线已经验收。尚待真人测试：短句/相似声线稳定性、麦克风采集、扬声器回声、自然打断、连续交流。只支持本次会话中的声线关联，不保证跨会话认出同一个人。

**尚不支持重叠语音的波形分离。** 严格模式过滤的是 ASR 的带声线转写；混在一条 ASR 结果里的旁人内容仍可能漏入，全部原始输入仍送火山 ASR。不能把本候选当成已通过的多人同时说话过滤器。

真人原始音频不落盘。日志仅展示于本次页面；开发验证回执只含合成素材。服务只监听回环地址；单会话 3 分钟、每进程最多 60 次对话调用、10 分钟输入及 6000 字 TTS。测试沿用约 5 美元单轮、总额不超 10 美元的实验预算，实际费用以供应商账单为准。

## 截图报错修正与延迟优化

普通话语出现“模型未声明模式变更依据”的原因：模型控制字段发生漂移，旧程序直接抛错；完整的旧策略说明又留在历史里，可能继续干扰后续判断。现在缺少切换依据时保留当前模式与对象，普通回应可以继续；越界的专注回复静默拦截。可选字段采用保守默认值，坏的引用不会获得切换权限。新增相应回归，当前 28 项测试通过，旧实验 7 项回归通过。

常规回复仅生成短的 reply/addresseeIds，只有变化时才生成身份或策略字段；历史只保留话语和回复，去掉重复策略理由、声线资料与引用。仍使用同一个 Doubao Seed 2.1 Lite，没有替换模型。回复默认一两句话，可继续追问。

TTS 按 NDJSON 帧读取，经 WebSocket 分段发送，浏览器支持 MP3 MediaSource 时立即缓冲播放，不支持时兼容整段播放。模型决策与语音合成不再共用串行队列；允许的插话会取消旧合成与播放，专注模式旁人和自适应模式普通旁聊不打断。真实抢话/AEC 听感仍待验收。

同一组 57.58 秒、8 次发言的合成输入，优化前后各 6 次真实模型调用，均能完成姓名推测、确认、明确交接及 2 次模型前过滤。以下是小样本中位数，不代表真人场景 p95：

| 指标 | 优化前 | 最终候选 |
|---|---:|---:|
| 模型耗时 | 3805 ms | 2470 ms |
| 停口到服务端可发送音频 | 6590 ms（整段） | 3755 ms（首段） |

最终候选说话人确认约 0.5–1.0 秒，模型 1.6–3.2 秒，TTS 首段 0.35–0.73 秒；首段总延迟约 2.5–4.5 秒。浏览器解码、缓冲和扬声器输出尚需额外时间；页面通过 playing 事件显示“估算停口到首音”，不是物理声学测量。语音流完整拼接后 FFmpeg 解码通过。

回执：`latency-before.json`、最终 `verification.json`（含分段 timings）；`latency-after.json` 曾暴露可选策略字段格式问题，不计为通过结果；`latency-after-v2.json` 为中间修复测量。最终以通过断言的 `verification.json` 为准。

7 次真实模型文字输入对照验证（`mode-verification.json`）：同一句旁人评论在 adaptive 保持安静，在 group 接话给所有人；旁人明确向 V 提问时一次回应但保留主要对象；“还是回答我，不要理他了”可以进入专注，后续附和和结束语不再连续报错。身份未知、待交接、姓名纠正的 6 次真实模型验证也通过（`model-edges.json`）。

页面新增“回放旁人评论 · 对照当前模式”，切换模式后可以回放相同 PCM。最初的短评论素材曾被 ASR 合并为同一 Speaker，不能算模式验证；这也表明短句声线合并仍是已知局限。对照素材改用更完整的发言，不加入声纹注册或人工绑定。

最终内置浏览器同音频对照（684 px 宽）：两种模式均自动得到 Speaker A=0、Speaker B=1；adaptive 对 B 评论保持安静且不打断 A，group 给 A/B 共同回应。MSE 流式音频 readyState=4、currentTime 持续前进、audio.error=null，页面播放事件回执估算本轮停口到首音 3095 ms。应用错误卡片和应用控制台错误均为 0，无横向溢出；工具自身的 Statsig 遥测失败不属于本页面。截图保存在 `/tmp/v-voice-adaptive-mode.png` 和 `/tmp/v-voice-group-mode.png`。测试结束后已释放会话并恢复默认自适应入口。
